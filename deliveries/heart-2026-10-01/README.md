# Heart 新交付包：2026-10-01

## 先读结论

这是一个独立的代码交付包，不是立即覆盖安装。**同伴已经自改心情插件，并已有 Live2D：默认保留它们。** 先把本包和她本地的代码做三方比较，再选择合并。共享库 `heart_shared` 也被心情使用，仅跳过 `heart_mood` 目录不等于完全没有影响，必须检查共享接口。

前一包基准是远端交付分支提交 `6d21b8eea3729779c589661b919ceb7e06b0b5ea` 中的 `heart-2026-09-30-vtuber-compat.zip`。本包的逐文件完整对比见 `与上次交付的全部区别.md`、`全部文件差异.json`、`previous-diffs/`。这不是同伴本地自改版的对比，后者只能由她的GPT在本机比较。

## 如何处理用户看到的“仍有四条重复摘要”

上午的检索记录会记下当时命中的四条摘要；下午清理后，历史记录仍应保留。但此前新卡片没有标明历史，容易被当成当前清单。

本次展示层用只读核对加“当前状态旁注”。正文折叠不等于改历史；完整事件和旧逐事件明细不动。缺少原生库或清理证据会标未核实，不以缺失ID猜测已删除，不用删除“不”等字符的算法去合并。候选被检索到也不代表最终回复实际采用。

本机涉及的四条旧摘要已经不在原生库，相关知识只剩一条有效摘要。本包**不含本机数据库和删除清单，不会替同伴删数据**。

## 文件对应关系

- `extensions/heart_shared/` → MaiBot根目录 `heart_shared/`：两个插件共用的审计/候选/冲突/日志库。
- `extensions/heart_*.py` → `src/services/`：宿主接入适配器，包含新的 `heart_memory_admin.py`。
- `plugins/heart_memory_audit/` → 同名插件目录。没有实际 `config.toml`；保留自己的配置。
- `plugins/heart_mood/`：完整参考版，默认不部署；特别核对 `appraiser.py`、`engine.py`、`emotions.py` 及本地兼容修改。
- `reference-maibot/`、`baseline-maibot/`、`patches/maibot/`：原生/前端现版本、干净基线与逐文件补丁。**完整参考文件不是要求整体覆盖**。
- `vtuber/`、`reference-vtuber/`、`patches/vtuber/`：可选平台参考，不含形象、模型字典、密钥或实际配置。由同伴GPT对照现有Open-LLM-VTuber接入。
- `tests/`、`pytests/`、校验脚本：虚构数据测试。本包缺少完整MaiBot环境，涉及原生模块的测试在合并后的宿主中运行。

## 安装顺序（交给同伴GPT）

1. 关闭MaiBot和WebUI。备份代码、自己的插件配置以及整个记忆/审计数据目录；这一步需要同伴本机操作。本包无真实数据备份。
2. 使用MaiBot虚拟环境Python运行 `verify_delivery.py`。不要把目录中附带测试产生的缓存/数据上传。
3. 阅读本包对比、原生说明和 `INSTALL_MANIFEST.json`；将上次包、本包、同伴现文件逐项比较。遇到本地自改文件先做合并计划，不能丢掉她的表情适配。
4. **仅预检，不安装**：

```powershell
& '你的MaiBot\.venv\Scripts\python.exe' '交付包\install_delivery.py' --target '你的MaiBot'
```

默认列出记忆、共享库、适配器，不选心情、原生、前端。未知现文件会标人工合并。原生变更可增加 `--include-native`；前端增加 `--include-dashboard`。不能因预检默认不选原生而误认为旧宿主足够，必须核对接口是否已有。

5. 若共享库/宿主/API匹配、无未知改动且GPT已完成兼容审查，才可加 `--apply --stopped --ack-shared-merge`。要选择心情必须额外加 `--include-mood`；仍不会覆盖指纹未知的自改文件。Live2D没有自动部署选项。**有未知文件时安装器整批不写**，请按差异人工合并，不要删除文件以绕开检查。
6. 心情自改版若要启用新卡片，只合并 `on_load` 中 `await asyncio.to_thread(self.store.start_card_logs)` 及已有 `asyncio` 导入，核对该入口非重复启动。不要为这行替换整个插件。新共享方法为新增，旧主要表/接口保留。
7. 前端合并后在真实 `dashboard` 根目录构建，不能在 `C:\Windows\System32` 执行相对命令。使用自己的Node：`node node_modules/vite/bin/vite.js build`，确认现环境类型检查/测试通过，再按宿主原有静态资源部署方式安装产物。本包不带预构建页面，避免覆盖同伴其它页面。
8. 首次启动先隔离QQ，检查插件载入、中文配置、WebUI及Live2D本地接口；之后恢复QQ。验证“喜欢Python/不喜欢Python”先冲突确认、“同意后更新”、自然语言忘记确认、群内隐私隔离、群回忆可编辑、模型超时不阻塞回复。

## 用户操作与日志位置

- `/记住 内容`：本人要求记住，仍检查已有内容和冲突；不能只因回复“记住了”就算写入。
- `/我的记忆`：个人事实列表。群里请求时私人部分私发本人；群中不公开私聊事实。
- `/群回忆`：当前群最近最多5条有效人物事实及摘要；可加关键词或 @ 人，但不读取私聊来源。
- 冲突：原群或私聊原会话询问本人，按机器人给出的 `/确认记忆更新 编号` 或取消操作。候选审核位于WebUI，不确定的群体摘要不让某个成员盲确认。
- 自然语言“忘掉我觉得C++很难这条记忆”：先定位本人目标并核实，确认后真正执行原生删除；以删除结果日志为准。
- WebUI长期记忆页的Heart管理区：选择实际群，审核待审候选（可先改正文）、删除审核记录、修改原生群回忆。删除候选记录不等于删除已存原生记忆；正式删除用原生页。
- 记忆配置可改 `auto_candidates.selection_guidance`、`conflicts.guidance`、`forget.guidance`、`summary_dedup.guidance` 等；安全身份/会话边界不会被提示词放宽。
- 心情配置可改模型、刺激上限/倍率、自定义分数区间风格、临时情绪、批次条数/最长等待；实际恢复到基线和AI刺激在日志中分别列出，不把恢复伪称为AI增减。
- 日志：`data/heart_observation/消息卡片/QQ`、`Live2D`、`其他`；传统逐事件明细 `logs/` 仍保留。今天及前三自然日明细自动清理；`每日概览/` 在次日首次启动补生成、永久保存。
- 卡片显示“处理中”时并不拖延回复；后续异步事件补齐。无关联证据的后台总结独立成卡，不能拿最近发言者冒充触发者。

## 回退与限制

题干核对：Lv1持续状态及风格、Lv2原生长期记忆生命周期/真实读写删除及审计有对应实现；Lv3已具备内部状态到平台表情的接口，但每个模型需要视觉验收；Lv4语音以及首反馈不超过10秒没有在本轮实现或验证。通用工具行动/中断控制也不是本包新增目标，不夸大功能覆盖。

可独立执行的安全检查：`python verify_delivery.py`、`python -m unittest test_delivery_safety -q`；使用宿主虚拟环境与导入路径后执行两插件测试：`python -m unittest discover -s tests -p "test_heart*.py" -q`。原生`pytests`在合并后的MaiBot根目录运行，避免误导入旧模块。`test_native_storage_contract.py`需完整宿主依赖。Live2D独立控制器：在本包`vtuber`中 `node scripts/test_heart_controller.mjs`，其它涉及整个平台的Python脚本在同伴现Live2D安装执行。

安装器代码备份在目标 `.runtime/heart-delivery-20261001-backup-*`，`ROLLBACK.json` 列出新旧文件。关闭后恢复需要回退的旧代码；新文件先核对再删除。数据库不要随意回退覆盖，否则丢失升级后状态和记录；新增展示表可保留，旧接口继续读原表。

测试可以降低风险，不能证明“任何可能的bug均不存在”；本轮未接QQ、未调用付费模型、未重开浏览器做真实表情验收。Live2D模型有哪些可见表情仍取决于形象资源，本插件只能发现并映射它拥有的表情，不能凭空创造动画。每个形象需同伴本机做视觉验收。
