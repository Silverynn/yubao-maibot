# StoryRoom 0.4 开发版：本次实现与验收

日期：2026-10-10。本版在独立目录开发，以 8791 为本机端口。原 8790 平台、同伴在线网址、QQ 与日常 VT 配置未切换。

## 已完成

| 功能 | 实现和验证 |
| --- | --- |
| 全局暂停、恢复 | 停止领取任务、失效旧结果、停止浏览器朗读；重启后暂停受控房间 |
| 人工接管与交还 AI | 人工主持权有续期及身份检查，移交后拒绝过期 GM 结果 |
| 时间回溯 | 恢复完整检查点，新建分支，保留旧历史与分支导出；调用量不回退 |
| 剧本记录 | 逐条保留说话者、叙事、行动及检定；当前分支和归档分支分别导出 |
| 三 AI 调度 | 两个 PC 加独立 GM，结构化操作由主机校验；模拟三 AI 跑完有限故事 |
| 最终物语子集 | 两属性骰、重大结果、PC 特质重投、物语点与资源台账，锁定结果防重复投骰 |
| 表情与素材 | 短暂表情五秒到期，默认中性；模型仍由共享主机供给浏览器 |
| 场景图片框架 | 生成、缓存、分支与版本检查、暂停后保留、调用上限；真实供应商未配置 |

## 实际测试结果

- Python：155 项测试通过，包括旧版兼容、真实 MaiBot SDK 清单校验、隔离数据库、并发版本保护、暂停与回溯、模拟三 AI 故事闭环、模拟图像。
- 前端：六组 Node 测试通过，覆盖语音、主持人发言锁、共享舞台、运行控制和时间回溯。
- 浏览器：在本机开发验收房间执行人工接管、恢复、发布带「界面验收」标记的叙事、暂停、检查点预览与回溯。确认新分支出现、旧分支保留、恢复后保持暂停。两位 Live2D 均可加载，默认状态显示平静。未检测到控制台错误。
- 上述测试没有调用付费语言模型或图片 API。模拟通过不能代替真实两台电脑的联调。

本机开发数据来自原平台的独立 SQLite 备份；原数据库当时没有房间，随后创建的是独立验收房间，并非复制同伴线上故事。

## 如何试用

打开 `http://127.0.0.1:8791/`。本机登录文件：工作区 `.runtime/StoryRoomNext/主持人登录密钥.txt`。界面验收所用的临时共同主持人权限将在验收结束后撤销，请用自己的本机文件登录。

人类试用：选择房间 → 我来接管主持人 → 开始 / 恢复游戏 → 发布叙事 → 暂停整场游戏。PC 未连接时不会收到真实角色回复。

AI 试用：配置主机模型和两张属性卡 → 确认两个 PC 在线 → 接管 → 交还 AI 主持人 → 开始 / 恢复游戏。完整部署、升级命令与覆盖范围见根目录 README。

回溯：暂停 → 加载检查点 → 选择节点 → 预览恢复状态 → 建立新分支并回溯。回溯后须重新选择人工或 AI 主持，再恢复。

关闭本机进程会保留数据。回溯不会退还已经花掉的 API 费用，也不能撤销已经在外部发生的行为。
