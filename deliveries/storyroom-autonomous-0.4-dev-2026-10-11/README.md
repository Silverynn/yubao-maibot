# StoryRoom 0.4 开发版：三 AI 跑团、回溯与主持接管

这是从同伴交付的 StoryRoom 0.3 连接修复版继续开发的独立版本。兼容原有 0.3 PC 协议；新增检定选择需要使用本包的 0.4 PC 插件。现有房间、QQ、个人 Open-LLM-VTuber 不会因启动本目录而被替换。

## 已实现的功能

- 房间级暂停与恢复：停止任务领取、拒绝晚到结果、取消可取消的生成；浏览器通过服务端事件及时停止朗读。
- 人类主持接管：与整场暂停分别控制。一个人持有主持权，另一人不能同时裁决；可释放、续期和交还 AI。
- 时间回溯：完整检查点恢复场景、角色卡、心情、信任、事实、记忆、检定与提案；建立新分支，旧未来可查看和导出。
- 三 AI 调度：两位 MaiBot PC 与独立 AI GM；公开叙事和受校验的系统操作分开。GM 使用主机配置，不获取管理员密钥。
- 真实台词剧本：按当前分支有效历史导出 Markdown，保留说话者、实际事件编号、规则结果及人工／AI 主持来源。
- 表情到期恢复：新回复触发的短暂表情五秒后回到中性，各浏览器使用共享状态。
- 最终物语属性检定子集：两项属性骰、大成功／大失败、玩家特质重投、物语点台账、资源状态与回溯。玩家选择由其自身模型处理。
- 场景背景：共享图片资源、公开场景提示词、异步生成、缓存、过期任务过滤、调用上限；图片失败不阻塞故事。

**不是完整的最终物语规则实现。** 此版尚未自动执行职业技能、战斗行动、伤害／抗性、升级、羁绊加值和扩展规则。规则界面会标注覆盖范围，AI 遇到这些内容应暂停等待处理。须取得你们采用的规则版本和两张正式角色卡后继续实现。现有有限章节与结局仍保留，不伪称已有无限世界生成。

基础资料：[官方介绍](https://need.games/fabula-ultima/)、[官方角色卡](https://www.needgames.it/wp-content/uploads/2022/11/Fabula-Ultima-Character-Sheet.pdf)。预填属性卡仅用于演示，职业构建与资源上限必须按实际角色卡核对。

## 本地试用

在 PowerShell 中进入本交付目录，执行：

```powershell
uv run --with-requirements requirements.txt python run.py --port 8791
```

打开 `http://127.0.0.1:8791/`。它与原平台的 8790 端口分开，个人 VT 仍使用原端口。

默认数据保存在本交付目录的 `.runtime` 中，登录密钥在该目录的 `主持人登录密钥.txt`。人工试用不需要模型密钥。需要 AI 主持时，从 `model-config.example.json` 复制出自己的 `model-config.json`，填入模型信息后按下文命令启动；真实配置、登录密钥和数据均不得提交 GitHub。只配置模型不会发起调用；点击交还 AI 并恢复运行后才会调用。

开始体验：

1. 登录后选择房间；确认两位 PC 在线。电脑之间使用主机的 HTTPS 地址，各 PC 使用本角色的密钥。
2. 点“我来接管主持人”，再点“开始／恢复游戏”，可输入主持叙事、回答和裁决。人类主持租约由持有它的页面续期，离线后不能继续裁决。
3. 若 GM 已配置，点“交还 AI 主持人”。它从当前事实、提案和真实检定接着主持；交还不会解除已有暂停。
4. 需要停止所有参与者时点“暂停整场游戏”。仅停止讨论或持有讲话按钮不等于全局暂停。
5. 回溯时先暂停，再加载检查点、预览状态、确认建立新分支。恢复后仍暂停，需要重新获取人类主持权或使用 AI 模式，再继续。
6. 下载当前剧本；归档分支仅供获准的主持人查看。查看旧剧本不重新调用模型或投骰。

默认本房间 GM 最多 100 次、PC 最多 200 次、图片最多 20 次调用。回溯不清零已消耗的调用量。费用无法回退，服务端取消请求也不能保证供应商停止计费。未配置图片服务时背景状态显示 `unconfigured`，不生成图片。

## 同伴主机部署

你们当前使用的同伴网址由同伴电脑提供。本机的 8791 开发版不能自动改动那个网址。把交付包中的主机代码部署到同伴主机，并分别升级两侧 PC 后，共享房间才具备新增功能。

先停机并使用 SQLite backup API 备份主机数据库；备份包括 WAL 已提交数据。用独立数据目录先验收，再决定正式切换。不要覆盖同伴的本机配置、模型、密钥或私有数据；原 0.3 数据可由新版本增量升级。只运行一个主机进程，不使用多个自动推进进程。

在交付目录运行（ZIP 解压后为 `storyroom-next`）。若已有固定版本前端库，可继续使用；缺失时先执行 `python scripts/setup_vendor.py`，它从固定 npm 版本下载并校验文件。角色与 Live2D Core 从共享主机已有的 Open-LLM-VTuber 目录读取，不随包再分发。

通用启动命令：

```powershell
uv run --with-requirements requirements.txt python run.py --port 8791 --data-dir ".runtime" --vtuber-root "你的Open-LLM-VTuber目录" --model-config "model-config.json"
```

从 `model-config.example.json` 复制出自己的 `model-config.json`，填入主机模型服务的实际地址、密钥和模型 ID。不要把真实配置发到群聊或公开仓库。没有模型配置时省略 `--model-config`，仍可人工主持。

`run.py` 仅监听本机。供同伴远程访问时，需由主机上已有的 HTTPS 反向代理转发到选定端口；原网址仍指向 8790 时，应在正式切换时将代理目标改成 8791，或停掉旧主机后用 `--port 8790` 启动本版。不要同时占用同一端口。需要语音识别时另传入已有服务的 `--asr-url`；本版不会自动替你启动 ASR 服务。

模型资源由共享主机提供，两位观看者只需浏览器加载。素材的许可证与授权仍按原模型要求保留。

升级 PC 前在 MaiBot 管理页关闭跑团连接，运行预检后安装，再重新开启。不能热覆盖正在工作的插件：

```powershell
python scripts/update_pc.py "你的MaiBot目录"
python scripts/update_pc.py "你的MaiBot目录" --apply
```

升级程序只接受已知版本指纹；发现同伴额外修改会停止，不会擅自覆盖。配置和数据保留，升级前源码备份可用于回退。连接地址仍需指向实际共享主机，安装源码不会替你修改房间地址。

## 背景服务

`images` 默认为 `null`。可另配置支持 `/images/generations` 的服务，字段为 `base_url`、`api_key`、`model`、可选的 `size`。此版要求服务直接返回 `data[0].b64_json` 格式的 PNG，不下载任意 URL。是否支持这些参数需核对所选服务。

场景变化才触发生图。结果绑定分支、运行版本和场景版本，旧未来的图不能覆盖现在；暂停后停止新任务并尽力取消生成。重启默认暂停，已经生成的同场景图片可复用。

## 测试与限制

```powershell
python -B -m unittest discover -s tests -p "test_*.py" -q
node --test tests/test_audio.mjs tests/test_author.mjs tests/test_media.mjs tests/test_stage.mjs tests/test_visual.mjs tests/test_runtime.mjs
```

完整 Python 测试需要已安装 MaiBot SDK；指定 `STORYROOM_MAIBOT_ROOT` 后可使用真实宿主清单校验器。测试使用临时房间、模拟模型和模拟图像，不连接 QQ，不调用付费 API。

实际跨两台电脑、真实模型与图像供应商的联调必须单独验收，不能用模拟通过代替。当前尚未修改同伴的在线主机。规则版本、职业技能及图像供应商仍待确定。

`README.upstream.md`、旧 `launch.py` 与其他旧启动程序仅为上游参考；本开发版入口是 `run.py`。[本次实现与验收](docs/本次实现与验收.md)记录实际验证范围。交付包使用独立清单和本次验证报告，不沿用旧 0.3 的验收结论。

交付包解压后可执行 `python scripts/verify_package.py` 核对文件指纹。包内不含模型素材、真实模型配置和数据库；共享主机继续使用已有、获授权的 Live2D 资源。
