# 与上次交付的区别

比较的是仓库中 `heart-2026-10-09`、独立选模增量，以及此前 StoryRoom 0.3 连接修复包。前两包是个人VT实时能力的基线，StoryRoom 更新已另行交付，本包不重复覆盖。

| 方面 | 上次 | 本次 |
|---|---|---|
| 阅读日志 | ASR、协议、播放采样和表情事件逐条展开 | 同次输入归为一个区块，临时识别/进度/后台复查汇总 |
| 分隔 | 多个过程可能有多条分隔或缺少输入归属 | 每次输入开头一条72个减号，内部不分隔；消息卡片也归组 |
| 工具观测 | 不易分辨请求时间和实际结果 | 真实await前后记录工具、查询、开始/返回/取消/耗时；阅读版显示开始及结果 |
| 草稿 | 协调器与宿主重复记录容易误当多次模型调用 | 优先宿主实际开始，只显示一份草稿和采用/丢弃结论 |
| 普通控制台 | 重复打印完整协议JSON | 只打印关键输入、行动/草稿结果和异常，详凭证仍保留 |
| 提前生成触发 | 相同文字不同revision也延长稳定等待 | 仅文字变化重置等待，每次语音仍最多一份草稿 |
| 录音结束 | 整段转写提交才标记停止听 | 原生前端通知input_end，结束后不新开草稿；已开始工作可完成 |
| 提前查询 | 查询目标随后续字词增长，多次重查 | 约0.65秒稳定等待，处理“查一下”和“我还……”边界 |
| 重启后连接 | VT可能缓存已失效的桥连接 | 显式失联通知、完整输入保持、下一轮重新绑定并保留开关 |
| 迟到音频 | 仅epoch不足以区分新连接 | connection_id隔离，旧连接同epoch片段也被拒绝 |
| 移植安装 | 完整包要分组件谨慎安装 | 增量一次更新两端；支持重命名插件，拒绝自改/重复插件/半套更新 |

11 个安装目标为：7 个共享日志文件 `cards.py`、`readable.py`、`storage.py`、`input_groups.py`、`realtime_readable.py`、`conversation_view.py`、`console_view.py`；实时插件 `engine.py`、`plugin.py`；VT `heart_realtime_client.py`、`frontend/heart-realtime.mjs`。每个变更均附基线（原先不存在的文件除外）与统一diff。

不修改 MaiBot/VT 主程序 `src`，不回退已交付的独立心情/记忆查重选模，不带个人人格提示词，不改语音包或用户配置，不修改 StoryRoom 0.3。包内少量主程序文件仅用于离线模拟测试，未列入安装清单。

提前查询仍是规则触发的本人事实/本地事实表读取，不是联网搜索或模型自由选工具。提前思考仍是隐藏 Replyer 草稿，不是提前运行整个 Planner，不能保证每次复用或减少费用。
