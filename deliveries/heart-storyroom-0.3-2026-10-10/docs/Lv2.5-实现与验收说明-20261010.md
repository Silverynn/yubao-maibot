# Lv2.5：本轮实现与验收范围

## 题干对应的数据流

已实现有限世界/阶段/分支/结局：创建房间时锁定剧本副本与哈希；推进只接受当前允许的边及条件，结局不能开启另一主线。角色以跑团角色卡、心情和合作信任保持连续性。角色生成发言和行动提案，GM裁决确认实际后果，后果成为角色经历，下次点名选择本角色有效经历进入提示词。失败的真实经历同样可以保留。

这是一个完整闭环：`现场 → 独立PC插件 → 本机模型 → 提案 → 真实投骰 → GM裁决 → 状态/经历 → 后续行动`。提案本身没有改世界的权限；PC不能指定投骰点数，重复投骰返回同一结果。不同GM的操作、上下文、模型输出、状态变化均可追溯。

世界线边界是结构约束和GM裁决共同保证：阶段ID、事实标记与合法跳转有强制验证；自然语言中的全部设定没有自动语义裁决，不能承诺任意模型绝不提出越界建议。

## 源码中主要机制

- `storyroom/store.py`：SQLite持久化、旧库备份/增量迁移、剧本锁定、现场版本、角色卡、一次性检定、裁决心情/信任、经历修正撤销及有限回忆。先筛选已确认叙事再限量，防止表情回执挤掉剧情。
- `storyroom/app.py`：GM/共同GM/PC权限、独立密钥、任务领取与结果、审计下载、表情回执、语音识别与开关日志。共同GM仅管理一个受邀房间。
- `plugins/storyroom_pc/plugin.py`：MaiBot SDK生命周期与管理页配置；只注册`llm.generate`能力，没有QQ消息钩子。默认关闭，不自动导入日常人格或私聊记忆。
- `worker.py`：主动轮询、有限故事提示词、严格JSON结果、实际输入输出审计、取消生成并丢弃旧输出、持久化待发送结果。网络恢复优先重发，不马上重调模型。
- `web/stage.js / visual.js`：两种形象共同渲染，使用各自情绪映射。修复了“同一表情返回false”和“动作忙碌”被当作表情失败的问题。
- `storyroom/speech.py / web/audio.js / media.js`：浏览器PCM转换为16k单声道WAV，复用平台已有ASR；分角色朗读、单交谈目标、连续收音、开口打断、完整识别提交、快速停止词、过期回调丢弃。语音不自动裁决事实。

## 为什么不直接复用原实时插件

原Heart Lv4.5接在VT的`/client-ws`、原会话绑定与原回复器；直接转发游戏内容到这个链路可能把日常聊天、记忆与工具权限带进跑团，也绕过GM裁决。本轮独立插件只借用模型接口，游戏上下文由StoryRoom提供。原实时插件仍用于原VT；StoryRoom连续模式是新桥接，不冒充它的全部能力。

## 兼容性结论

验收环境：MaiBot1.2.5、SDK2.8.1、Python3.12.14、Windows。SDK配置、生命周期和能力参数已实际导入验证，模型接口模拟。版本范围只是插件声明，其他版本仍需重新测试。

原心情插件、长期记忆插件、QQ语音识别插件没有被修改；StoryRoom不注册日常聊天Hook。新增游戏心情/经历写在独立房间库，不覆盖原心情。QQ私聊/多人群聊的处理入口未改，本轮没有向真实QQ发送测试消息。

本机三种Live2D资源的文件及情绪映射预检通过，实际网页验证月铃与旧鱼宝两个形象；伙伴真实新形象未取得资源，不能据此保证任意模型映射正常。共享舞台要在平台主机配置已授权的两份资源。

伙伴原ASR/TTS、语音包与VT配置保留；StoryRoom暂用系统本地朗读声线，不自动接入伙伴定制TTS。ASR只接已有本地兼容接口，可不配置。当前本机SenseVoice服务免费健康检查为ready，真人发音效果尚需手动验收。

## 本轮验证

85项Python离线检查通过：状态与权限、有限故事、旧库迁移/备份、记忆更新撤销、行动检定、真实本机HTTP两个模拟PC、生成期间取消、断线结果恢复、SDK配置与生命周期、语音格式/权限/失败日志、安装保护。模型和ASR均使用模拟返回，不消耗收费额度。

前端27项断言通过：4项Live2D语义、7项音频编码/快速停止词、16项角色开关隔离/单目标/取消/日志。Node验证不替代真人麦克风测试。

真实浏览器验收：两位Live2D显示，按映射切换表情；离线演示提案、锁定检定、投骰、GM裁决、心情/经历；新增语音开关、交谈角色选择、键盘完整输入与快速停止记录。浏览器具备中文系统本地声音。没有自动打开麦克风或实际试听录音。

安装演练确认默认关闭、已有目录拒绝覆盖、保留别的插件；正式本机安装只新增默认关闭的PC插件，不重启MaiBot。

## 暂时不足与后续顺序

1. **真正异地联调**：远程接口与权限已实现；公网HTTPS地址、证书、资源展示许可与伙伴电脑验收未完成。先共同确定平台运营方式，再验收两台PC和两位GM。
2. **原声线与嘴型**：现有VT语音包未替换，StoryRoom只提供系统朗读。可加独立TTS适配接口、分角色voice配置、开始/停止/完成回执和嘴型驱动。
3. **完整Lv4.5**：连续收音、规则停止、开口打断和取消已有；边听边查、提前生成、晚到证据纠正尚未接入游戏。后续应把它们接到带房间版本的只读查询与PC草稿，所有事实仍由GM确认。
4. **连续模式仍是分回合**：识别期间不收下一句，VAD为音量阈值，嘈杂环境会误触发。可升级AudioWorklet、专门VAD、音频队列和真正流式ASR；目前不能称为自然电话交流。
5. **剧本编辑/背景**：目前手工JSON与CSS场景，没有图形编辑、背景上传/预览、复杂D&D/CoC规则或动态多角色队伍。先添加剧本校验与编辑预览，再开放素材管理。
6. **记忆策略**：经历最多8条，同阶段优先，修改/撤销需GM操作；没有自动关系演化或模型判定遗忘。审计保留原文，撤销不回滚已确认世界标记。
7. **取消与计费**：插件取消本地等待且不提交旧结果；无法保证模型供应商停止计费。生成完成前进程崩溃、租约过期也不能保证收费调用恰好一次。可进一步加任务幂等键和模型请求恢复。

这些边界不会阻止验证Lv2.5的主要思路，但应在展示与面试时如实说明。不要把离线通过或页面出现开关等同于所有真人语音及公网场景已验收。
