# Heart 实时对话插件（Lv4.5）

本地独立 MaiBot SDK 2.8.1 插件，插件编号 `heart.realtime`。当前安装是本地版本，清单仓库链接指向所属项目，尚未推送插件源码。

实时策略、只读检索、并发取消和审计位于本目录。MaiBot 宿主接缝负责取消本人原生推理及保存真实播放结果；VT 接缝负责取原麦克风的帧、使用原 MaiBot 角色和声带、停止旧播放、回传播放状态。

## 使用

当前版本 0.2.1。正常使用桌面 Live2D 入口，刷新页面可见两个外置开关：「☎ 实时插件」和「⚡ 提前生成」。默认都关闭；提前生成开启会同时开启实时插件。提前生成说明为「在你说话时就开始生成回答，加快回答速度但可能增加模型用量」。使用原麦克风按钮录音；原 QQ 入口继续使用原识别插件，回复仍为文字。

## 路线2：有限提前生成

不对每条临时转写都请求大模型。只有语音输入的临时文字保持稳定 0.65 秒、长度合理、不含明确副作用请求且所需查询已经返回时，才尝试准备草稿。每轮最多一次；用户改口后丢弃，不在这一轮反复重做。草稿输入确认前隐藏，不写成正式用户消息或角色回复。

完整转写仍经过 MaiBot 原生规划器。规划器决定回复后，原生 Replyer 检查正式输入、历史、人设、心情、模型、证据以及其他插件 Hook。全部匹配才采用草稿，省去这一次 Replyer 请求；任何额外回复参考或条件都会丢弃草稿，按原生要求生成。正常规划器经常提供新的参考，因此实际复用率可能偏低，不承诺节省每轮费用。采用草稿也不跳过规划器、表达选择、后处理和播放回执。

等待查询分两种期限：说完时最多等 1 秒，超过后查询仍在后台运行；整个查询最多 4 秒，包括排队和本地事实读取。查询晚到时，将最新材料接入本轮 Replyer。正在生成时最多取消重生成一次；已经排队/播放则冻结旧输出，补充或纠正。证据再次变化超过预算时明确报错，不无限重试。这里根据材料指纹判断变化，未额外调用模型做“是否影响答案”的语义判定。

## 实时协调

- 说话未结束：本地流式 Zipformer 输出临时转写；只读意图「查一下」「核实」「还记得」等提前检索本人原生记忆及管理员事实表，不提交正式用户输入或副作用。
- 开始插话：先暂停浏览器声音，再取消当前访客的 MaiBot 推理、VT/TTS 等待及旧只读任务。世代号阻止迟到声音和旧播放回执。
- 特殊短句：「停一下」「别说了」等精确匹配直接停止；点名应答读取 MaiBot 当前 nickname 和 alias_names，例如角色名是「小明」，则「小明」「小明在吗」直接反馈。也可用 character_names 配置 Live2D 的不同名字。语音应答缓存未就绪时给文字反馈并明确记日志。
- 澄清：同一查询匹配多条管理员事实时适时提示；声带开启时可用原声带问清，用户已结束本轮时不迟到插话。
- 更正：边播放边检查同一事实表条目的版本；值改变且旧值出现在已播放/正在播放正文时停止旧稿，让原 MaiBot 接受系统更正任务，收回旧值并依据新证据表达。不创建假用户消息，不把任意检索排序变化当矛盾。
- 播放账本：排队、开始、进度、播放完成、停止、失败分别记录；仅收到完整句播放完成或纯文字真实显示回执后保存正式回复。部分播放只有秒数，不猜测听到了哪几个字。

## 边界与配置

默认插件端口 12396，流式模型端口 12397，均仅本机。VT 后端凭据保存在 SDK runtime 目录，不交给网页。4 个网页连接上限、90 秒单段音频上限、512 项内存账本上限、2 个会话只读工作槽、查询超时及澄清冷却。

复制 `settings.example.json` 为自己的 `settings.json`；后者不加入 Git，不从其他电脑直接照搬。路径可以是绝对路径，也可以相对于插件目录。默认 asr_python 为空表示当前 Python；model 指向插件内 models/ 下的模型；asr_dependencies 指向插件内隔离依赖，也允许指向本机已有环境。不要复制其他操作系统或 Python 版本的二进制依赖。

`settings.json` 可覆盖 `enabled`、`port`、`asr_port`、`asr_python`、`model`、`asr_dependencies`、`character_names`、`facts_file` 和时间预算。环境变量 HEART_RT_ASR_PYTHON、HEART_RT_MODEL、HEART_RT_ASR_DEPS 优先于文件配置；修改后重载插件。流式模型启动前实际导入所选 Python 的依赖，缺文件、旧识别库、二进制不匹配会记录「兼容性检查」失败，绝不自动安装或换掉普通识别服务。用本机 Python 执行 check_compatibility.py 可以单独诊断，无须启动机器人。

VT 后端需要 HEART_MAIBOT_ROOT 指向本机 MaiBot 根目录。如果重命名了插件目录，可额外配置 HEART_REALTIME_PLUGIN_DIR 指向实际插件文件夹。端口由运行时文件发现，不固定要求 12396。前端和 VT 后端可以使用不同端口，但实时接入只识别同一主机（或 localhost/127.0.0.1 别名）上的 /client-ws；不同主机或改了反向代理路径还需要适配。

## 同步给伙伴时的接入条件

验证基线是 MaiBot 1.2.5、SDK 2.8.1、Open-LLM-VTuber 1.2.1 的本项目 Heart 集成版本。清单声明已测版本，不再宣称未来整个版本范围都兼容。当前 SDK 对同一个小版本下更高的补丁版本（例如1.2.6）会警告后尝试兼容加载，这是 SDK 的既有策略，不等同于已通过本插件测试；越过该范围的1.3.0会被拒绝。插件与宿主 bind 接口另使用 api_version=1；接口不匹配会明确拒绝启用。切换 MaiBot/SDK 版本时先移植宿主接口并运行回归，再调整清单。

独立插件目录负责实时策略，但不能只复制这个目录到原版 MaiBot 就获得完整能力。还需要：MaiBot 的 heart_shared 日志支持、Heart 记忆/Live2D 交付接入、heart_realtime.py/heart_realtime_drafts.py 以及注册/发送/Replyer 接缝；VT 的 heart_realtime_client.py、voice_context.py、Heart 桥接/对话审计及原 VAD/播放队列接缝。共享包提供相对路径补丁和接入清单；保留伙伴已有修改，补丁不匹配时手工合并。

实时模块没有固定的表情名、表情序号或声带名称。TTS 使用当前 VT context.tts_engine；角色字幕使用当前 character_config；原生播放链路继续处理各自模型的动作。Heart 表情桥接应保留当前动态 expression_catalog/model_provider 实现，不要用旧版只适配本地模型的文件覆盖它。这说明实时模块不绑定本地形象，并不保证任意第三方模型的驱动都已实机验证。

分享时只包含源码、空 facts 示例和配置模板；不包含 settings.json、runtime-location.json、密钥、数据库、用户日志、录音、模型权重、虚拟环境或二进制依赖。每台电脑自行配置识别环境和模型位置。原普通语音识别/QQ识别/TTS继续使用原有配置。

`facts.json` 默认空表，不能填入假的业务事实。演示更正时可加入真实受控事实，例如管理员确认的会议：

```json
{"会议时间":{"value":"16:00","version":"1","aliases":["会议"]}}
```

开始播放包含旧值的回答时，将同一条目的真实值及版本更新；插件每 2 秒核实一次，最长 90 秒。这是有限的、可验证的同源事实更正机制，不承诺任意网页或所有知识的语义矛盾都能自动判断。只读检索已接原生长期记忆；可扩展的其他检索工具需要明确证据键和版本约定。

QQ 多人消息只观察原生会话、消息编号、发送者；任何群成员说「停一下」不会取消另一个成员或 Live2D 的任务。Live2D 同一连接内的多人语音房暂不开放。

## 日志与故障

功能名、输入、临时转写、工具结果、正文、播放秒数、取消及失败写入 MaiBot 标准日志、Heart SQLite `实时对话插件` 事件、SDK data 下 `YYYY-MM-DD-realtime.jsonl`。不记录原始录音或桥接密钥。

`plugin_loaded` 表示插件包已加载；`plugin_enabled/session_enabled` 表示该消息所在会话用了实时链路；`preemptive_enabled` 表示提前生成开关开启。关闭插件后的正式 Live2D 输入和 QQ 消息也记录关闭状态。原生草稿缓存日志位于 Heart SQLite，包含 started/ready/adopted/discarded/regenerated、正文、模型用量计数及关联消息编号。SDK JSONL 记录协调流程；两者用会话、发言和正式消息编号关联，不把 ready 当成已采用。

## 已知限制

- 稳定停顿是简单规则，不是模型判断用户是否真正说完；两种 ASR 转写不同会使草稿失效。
- 为保留原生人格/规划和其他插件行为，复用检查保守。开启路线2后可能多花一次草稿费用；本机取消不能保证云端不计费。
- 材料变化不等同于答案必然错误，可能产生一次不必要的重生成。更精细的判断需要可引用的事实键，或另加有预算的语义判断。
- 查询范围是已接入的本人记忆与管理员事实表；任意互联网资料的通用语义纠错、自动判断每个插话时机、多用户同一麦克风、已播放半句的字级定位尚未实现。
- 受控事实变化可纠正，但不保证所有角色判断都能自动纠正。真人麦克风、扬声器和 QQ 群实发需单独验收。

运行时错误明确显示/记录；不要假装失败动作成功。实时接口失败时先关闭实时按钮再使用普通链路。插件卸载只结束自己创建的模型进程，不按端口停止用户的服务。

## 模型及依赖来源

流式模型：[sherpa-onnx 官方模型说明](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-transducer/zipformer-transducer-models.html)，下载 `sherpa-onnx-streaming-zipformer-zh-int8-2025-06-30` 官方发布包。模型目录含下载来源和 SHA256 清单，未复制用户对话用于训练。

原 VT 的 sherpa-onnx 1.10.46 不兼容此模型的特征处理。1.13.8 及对应 core 在 `asr-dependencies` 隔离安装，流式子进程使用它；未升级原 VT/MaiBot 环境。识别过程使用 VT 已有的 aiohttp、numpy 和 Python 3.11。

运行自动测试的说明与实际验证范围见交付目录中的安装验证报告；自动回放不等于真人麦克风或真实多人 QQ 验收。
