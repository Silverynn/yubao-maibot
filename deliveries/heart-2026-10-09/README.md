## 文件怎样使用

| 目录 | 对应位置与用途 |
| --- | --- |
| `maibot/` | MaiBot 的相对路径源码；配置和实际事实库不在其中 |
| `vt/` | Open-LLM-VTuber 的配套参考；须保留同伴的语音/形象接入并做三方合并 |
| `baseline/` | 前包已提供的旧源码，或注明来源的上游版本；供三方比较 |
| `patches/` | 与各条基线对应的逐文件差异；不应把所有补丁盲目执行一遍 |
| `speech/` | 可选本机整段识别服务；有现成语音包时不安装 |
| `tools/` | 只读预检、受保护安装、前端接缝预检、跨目录日志观察 |
| `tests/` | 模拟模型/前端、安装安全、动态表情、显示检查 |
| `examples/` | 空事实模板与明确标注的虚构验收事实；不替换现有库 |

`INSTALL_MANIFEST.json` 的 `component` 为 `mood`、`asr`、`vt-voice-reference`、`vt-legacy-reference` 的项均非默认安装项。`vt-voice-reference` 提供部分已有本机声带实现作比较，不要求使用 Moonbell；`vt-legacy-reference` 是旧形象的计时兼容参考，不推广为通用表情行为。

## 验证与安装

使用自己的 Python 和路径，先校验：

```text
python tools/verify_delivery.py
python -B -m unittest discover -s tests -p "test_*.py" -q
python -B tests/check_display.py
node tests/test_frontend_route2.mjs
python tools/install_delivery.py --maibot-root "你的MaiBot目录"
```

最后一行只比较，不安装。`conflict` 表示缺失基线或同伴已改，不能加参数强行覆盖；先按 `baseline`、`patches` 和她的现文件合并。全部审阅、停服务后，才按 AI 安装说明给出的组件范围执行 `--apply --stopped --reviewed`。工具不下载依赖、不启动 QQ、不操作账号或记忆库。

已经有不同版本或源码改动的伙伴，正常结果很可能是需要人工合并。版本号一致也不证明接口一致。已对照 MaiBot 1.2.5、SDK 2.8.1、VT 1.2.1；其他源码/前端构建须重新验收。
