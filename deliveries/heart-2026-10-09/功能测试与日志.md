# 同伴本机测试：用自己的声音和形象验收

先按安装交接合并。先不开实时插件测试原文字、录音和原 TTS；保持声音、音量、声线、表情与升级前正常，再测试新增功能。可以先在不连真实群的环境验证接口，由同伴决定何时联机。

日志观察（只读，Ctrl+C 只退出观察）：

```text
python tools/watch_events.py --maibot-root "本机MaiBot目录" --follow
```

| 开关/功能 | 操作 | 预期和日志 |
| --- | --- | --- |
| 实时关、提前生成关 | 文字“你好”，再用原麦克风说“我今天准备去图书馆” | 普通转写与原声音正常；plugin_enabled=false，没有提前请求 |
| 实时开、提前生成关 | 说一段普通话，观察页面 | 出现正在听/临时文字，partial标temporary=true；最终识别才是accepted正式输入 |
| 短句快反应 | 只说“你在吗？” | 短句快反应/completed；声音缓存未准备时可能仅文字 |
| 打断 | AI长答时开麦说“停一下” | 停止原声音，旧世代迟到音频不继续播放；插话与取消、stopped或discarded |
| 换话题 | 播放中说“等一下，我换个问题，怎样安排复习？” | 旧任务取消，新问题继续；不能把旧答案后半段补播 |
| 边听边查 | “还记得我喜欢什么饮料吗？我想确认一下以前聊过的偏好。” | started含查询词、completed含结果；无记忆时允许无结果。不是任意互联网搜索 |
| 提前生成 | 两个开关都开，20秒内口述一个明确问题 | 临时文字稳定约0.65秒才可能started；ready不是采用，adopted才是复用 |
| 改口取消 | 看到提前准备后继续说“我改一下，我想问怎样复习” | discarded，正式回答依据完整输入；一轮不无限重做草稿 |
| 播放账本 | 一轮播完，一轮中途打断 | completed/committed与stopped区分，未听完整的整段不标为完整播放；前面已播完的句子可保留 |
| 关闭恢复 | 关实时插件，再录音和打字 | 原链路正常，两个实时开关均为false |
| 两套形象 | 切换她自己的两个模型，再触发情绪/说话 | 表情来自当前形象，不使用作者模型固定编号；不支持的表情有明确回退/日志 |

首反馈从提交文字或本段语音结束开始计时，10秒内应有可感知状态，不要求完整答案10秒内生成。录屏观察真实浏览器比单看后台数字可靠。

提前生成不是每轮必触发：打字、长停顿导致VAD提前结束、文本持续变化、包含副作用请求、查询未完成、正式上下文改变等都可能不触发或弃用。`approval` 也不等于真的请求过模型。观察 started、usage、adopted，不靠机器人自称“提前想过”。

## 澄清、纠正、晚到结果

管理员自愿使用 `examples/验收事实样例.json` 做测试时，先备份本机 facts.json；已有正式数据只新增测试项，不覆盖。结束后移除测试项或恢复备份。

- 澄清：开实时、关提前生成，说“查一下验收会议时间”，继续本轮发言。两个同名别名匹配且查询在说话期间完成时，应提示选哪项；看“适时澄清”。随后说“查一下验收项目晨会的时间”收窄范围。
- 中途纠正：问晨会时间并请原样输出时间数字、较长介绍准备事项。实际回答出现09:00且仍在播放时，用键盘把同一条晨会value改成10:00、version改成验收2。约2秒轮询发现变化后，观察 evidence_changed、requested及纠正正文。仅改文件或口头说“你错了”不算验证。
- 限制：旧值被改写成“九点”时精确匹配可能未命中；已全播完、换话题后可能结束监测。不是通用语义纠错系统。
- 查询晚到：最终输入最多等1秒，查询整体预算4秒。wait_budget_exceeded是不再等待但后台仍跑；late_adopted是材料接入；regenerated是旧稿重生成；requested是补充/纠正；timeout是该次查询截止。不能靠“请查慢一点”可靠触发，离线模拟测试覆盖这些分支，真实聊天没遇到不必强造。

## QQ 多人

在允许回复的测试群中，甲说喜欢茶、乙说喜欢可可，丙问谁喜欢茶；检查发送者、原消息编号及引用归属。再让多人交替发语音，看原 ASR 的每条转写是否归属正确。

QQ完整消息始终是正式消息；某人说“停一下”不应调用Live2D打断。QQ应继续只用文字回复。群规划器可合并多条或暂不回应某条，不能把不逐条回复直接判成隔离失败。已有QQ ASR如果不属于本包，需由其适配层提供相同语音观测字段；不要为了日志重复识别一次音频。

## 日志字段

`plugin_enabled/preemptive_enabled`看会话开关，`feature/phase`看功能与阶段，`input/text/output/result`看实际内容，`reason`看取消或失败原因，`utterance_id/message_id/sender_id`看归属，`epoch/clip_id/position_seconds`看输出与播放，`model/usage`看实际模型请求计数。不同事件字段不同；缺失不是false。未生成正式消息前message_id可以为空。

协调日志在 `data/plugins/heart.realtime/日期-realtime.jsonl`，完整Heart事件在 `data/heart_observation/events.sqlite3`。不要把实际私人日志上传GitHub。报错时向维护者提供脱敏后的时间、开关、功能名、原因即可。
