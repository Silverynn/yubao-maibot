# 给同伴 GPT：StoryRoom 0.3 安装与联机指南

本包接续上次 StoryRoom 0.2 交付。新增可编辑剧本、隔离跑团记忆、持续旁听与自主讨论。按用户授权安装独立平台和 PC 插件，先检查实际运行目录，保留同伴自己修改的代码、语音包和配置。下载仓库不代表已经安装到运行实例。

## 本次连接修复：先读这一段

最新交付目录为 `heart-storyroom-0.3-connect-fix-2026-10-10`，协议继续为0.3，插件版本继续为0.3.0。旧0.3包曾缺少必需清单字段，不能仅凭版本号判断是否已修复。若出现“manifest校验失败：author.url / urls / i18n”，问题发生在加载入口，玩家密钥尚未被使用；不要重新申请密钥、修改模型API key或绕过宿主校验。

只作为玩家加入的一方，主要更新 `plugins/storyroom_pc`，不必启动第二个平台，也不必重装个人Live2D、ASR/TTS、心情或记忆插件。原始0.3发布版已加入升级器的已知指纹，可按下面升级命令修复；有自改代码时仍会停止，不能强制覆盖。具体步骤见 [给伙伴GPT：连接修复操作单](给伙伴GPT-连接修复操作单-20261010.md)。

主机房间里的两位角色现在叫“故机”和“鱼宝”，身份ID与玩家密钥沿用原值。鱼宝使用伙伴交付的 `yubao-fullbody` 模型；PC插件不自动上传模型。已有主机已安装资源，伙伴不用更改自己的日常VT模型或声线。

## 1. 先确定谁运行平台

只运行一份共享 StoryRoom。两台 MaiBot 分别运行“Heart 跑团PC连接”，访问同一个平台，各自调用本机模型。只加入游戏的一方不用再启动第二个平台，不用安装平台前端库或另一位的 Live2D。

```text
双方浏览器 → 一个 HTTPS StoryRoom（房间、剧本、两套模型、跑团记忆）
                    ↑                 ↑
                甲的 PC 插件       乙的 PC 插件
                甲的 MaiBot        乙的 MaiBot
```

先确认：平台运营方、共同访问地址、自己的 PC 密钥、希望展示的模型。缺少地址或密钥时先完成离线安装，保持插件关闭，不猜测地址或借用主持人密钥。

127.0.0.1 是自己的电脑，不能发给异地伙伴。交付没有自动部署公网通路；需要运营方提供有效证书的 HTTPS 根地址。不要使用 /storyroom/ 子路径，本页接口与资源采用根路径。

## 2. 核对实际环境与包

已验收 Windows / Python 3.12 / MaiBot 1.2.5 / SDK 2.8.1。manifest 的版本范围不是所有版本均实测的保证。使用实际 MaiBot 的 Python，把示例路径改成真实目录：

```powershell
$roomDir = 'D:\StoryRoom新交付包'
$botDir = 'D:\实际MaiBot'
$botPython = Join-Path $botDir '.venv\Scripts\python.exe'
Set-Location -LiteralPath $roomDir
& $botPython -X utf8 -B "$roomDir\scripts\verify_package.py"
& $botPython -X utf8 -B "$roomDir\scripts\check_compat.py" --maibot-root $botDir
```

优先下载 ZIP 解压，避免 Git 自动转换换行导致 SHA256 不符。SDK 不同时先隔离验证 llm.generate 的 model_name、max_tokens、request_timeout_seconds、timeout_ms 参数，不擅自更新主程序。只补缺失依赖。本次不含 MaiBot 主程序补丁，不重装原心情、记忆、QQ ASR 或 VT 实时插件。

## 3. PC 插件初装或升级，选一种

先关闭跑团连接，再停止插件或正常停止 MaiBot；安装器不替用户重启。保留配置、数据和独立 Git。备份含密钥，不能上传。

首次安装、没有 plugins/storyroom_pc：

```powershell
& $botPython -X utf8 -B "$roomDir\scripts\install_pc.py" $botDir
& $botPython -X utf8 -B "$roomDir\scripts\install_pc.py" $botDir --install
```

已经安装上次0.2、上次有清单错误的原始0.3、或核对已修复的相同0.3：

```powershell
& $botPython -X utf8 -B "$roomDir\scripts\update_pc.py" $botDir
& $botPython -X utf8 -B "$roomDir\scripts\update_pc.py" $botDir --apply
```

升级器校验五份已发布源码，备份并保留 config.toml、.git 和数据。发现同伴自改就停止：用上次发布版、同伴现版、本次发布版三方比较并合并，不能删除旧目录或篡改指纹绕过保护。旧 plugin.config_version 字符串保留，不用它判断协议；查看 _manifest.json 的0.3.0及握手日志。

源码安装后再对实际副本运行原生校验，确认错误不再出现。插件源码监视开启时可热加载；未开启时正常重启MaiBot，不要求关闭普通网页。刷新管理页后必须看到加载成功，再启用连接。伙伴用自己的PC密钥，主机不提供它自己的故机密钥。

## 4. 共享平台准备（仅平台主机）

平台与双方PC均须0.3，不能混用0.2。平台升级前关闭StoryRoom启动窗口，先一致备份整个 .runtime（含SQLite WAL/SHM）、local-config.json及自改源码。按新包清单更新公开源码；保留 .runtime、local-config.json、web/vendor、模型、Core、权重与自编故事文件。同名故事或自改源码先比较。不要整目录覆盖或删除旧目录；本次没有自动覆盖平台的脚本，安装助手需要核对来源和差异。

首次启动0.3在 .runtime/备份 中通过SQLite backup备份旧库，再增量迁移，保留房间与密钥。不能用0.2程序直接读取升级后的库；回退需停机后恢复一致的0.2源码与迁移前数据库备份。

新主机才准备 requirements.txt 缺失依赖，复制 local-config.example.json 为 local-config.json，填自己的Python、VT资源根目录与端口。没有ASR将 asr_url 设为空字符串，仍可键盘跑团。已有 web/vendor 满足 vendor-manifest.json 就保留；缺失才运行 scripts/setup_vendor.py。模型、Core、语音权重不随包分发。

平台可复用OpenAI格式本地ASR：multipart的file字段、WAV音频、JSON返回text，只接受主机loopback HTTP地址。伙伴的ASR/TTS类型不保证全部自动适配。伙伴定制语音包保留，共享舞台暂用浏览器系统朗读。

双击 start.cmd 本机检查。异地由运营方将HTTPS代理/隧道指向主机127.0.0.1:8790。保留外部Host、转发 X-Forwarded-Proto: https，Uvicorn只信任实际代理来源；非本机代理需专门部署配置，默认本机启动不自动适配。验证同源POST不报403、登录cookie具有Secure属性、认证后模型可加载。不关闭同源或证书检查，不开放MaiBot管理端口、ASR或模型接口。

## 5. 对方Live2D的资源与表情

平台主机需要两套完整模型：model3.json、moc3、贴图、表情、引用到的动作，并确认展示授权。vtuber_root 指向含 model_dict.json、live2d-models、frontend/libs/live2dcubismcore.min.js 的根目录。

保留现有 model_dict.json 条目，新增伙伴唯一name、/live2d-models/.../xxx.model3.json入口及按实际名称或索引配置的emotionMap。键包括neutral、joy、confusion、anger、sadness、surprise、blush、thinking；有动作时加expressionMotions。不要覆盖伙伴原模型、映射或声线。

```powershell
& $botPython -X utf8 -B "$roomDir\scripts\check_compat.py" --vtuber-root 'D:\实际Open-LLM-VTuber'
```

模型目录与映射在启动时读取；新增后正常重启平台，再新建房间选择正确模型。目前没有房间内换avatar的网页入口；已有房间需要保留时应先设计迁移，不能直接改数据库。示例第二位鲸鱼女孩是占位，不代表伙伴新形象已接入。

双方浏览器自动从平台加载素材，不需手动安装另一位模型。PC插件发送回复与情绪，不上传模型，也不镜像个人VT窗口。跑团表情由本团任务/状态驱动，缺少表情回退中性并记录原因，配置不能创造动画。远端实际资源加载仍需两人现场验收。

## 6. 配置连接和权限

管理员用 .runtime/主持人登录密钥.txt 登录创建房间，私下分配两个不同PC密钥。正常重启/刷新插件后，双方填写：

| 配置 | 填写 |
|---|---|
| connection.server_url | 同一个HTTPS根地址；本机验收可用http://127.0.0.1:8790 |
| connection.player_token | 自己的PC密钥，不是GM密钥或模型API key |
| connection.trust_env | 默认false，确需系统代理再开 |
| character.identity/guidance | 本团愿意共享的身份和说话方式 |
| character.model_name | 留空复用replyer，或本机已配置模型name |
| connection.enabled | 上述完成后再开启 |

浏览器用PC密钥可进入角色房间。伙伴要主持权限则另生成仅本房间GM密钥；浏览器填GM密钥，插件仍填PC密钥。修改地址或密钥会隔离旧暂存，不把旧回复发到新目标。

/health 应为service=storyroom、version=0.3.0、protocol=0.3。双方显示在线并握手成功后，主持人介绍现场，点击“介绍结束 / 继续自主讨论”。现在无需逐句点名：机器人轮流讨论、提问或提出行动，等待回答/裁决后继续。默认两位合计4次连续发言，可设1～20；点名保留供单独询问。

## 7. 测试与日志

免费离线测试（临时数据和模拟模型）：

```powershell
$env:STORYROOM_MAIBOT_ROOT = $botDir
& $botPython -X utf8 -B -m unittest discover -s "$roomDir\tests" -v
```

有Node时运行tests/test_visual.mjs、test_audio.mjs、test_media.mjs、test_author.mjs、test_stage.mjs。本次打包验证138项Python测试、54项前端断言，包含宿主原生清单校验和原始0.3修复升级演练。之后按 [0.3分步教程](StoryRoom-0.3-使用教程与已知缺陷-20261010.md) 验收：

1. PC关闭时检查旧房间、模板、双模型；编辑模板不会自动改变当前房间。
2. 用户准备真实模型测试时开启PC。仅在线旁听日志model_called=false；开放讨论才出现提示词、输出、意图与耗时。
3. 测相互讨论、向GM提问、提出行动；GM回答/裁决后下一轮读到新事实，期望结果不能自行变成事实。
4. 增加/修正/撤销房间记忆与其他玩家资料，检查memory_namespace、room_memory、other_players；日常QQ/VT不注入团内资料。
5. GM按讲话键/使用网页麦克风时，新调用和输出暂停；机器人朗读时下一位等待。外部电话不自动受锁控制。
6. 双方看到同一角色表情及映射回执；分别测朗读开关、所选角色语音输入、停止和取消。

PC日志：MaiBot/data/plugins/heart.storyroom-pc/日志/YYYY-MM-DD.jsonl。平台日志：.runtime/日志/房间名称_短编号/YYYY-MM-DD.txt。网页下载行动记录查看上下文、意图、输出与裁决。docs/StoryRoom-0.3-模拟验收日志-20261010.json明确为模拟示例。

不上传用户config.toml、local-config.json、.runtime、数据库、日志、密钥、pending-result.json、observer.json、升级备份、模型或语音包。安装报告只展示版本、源码指纹与验收结果。

## 8. 已知边界与回退

固定两位AI；真人/NPC可录入资料和公共交流。持续同步不代表逐条模型推理；普通晚到聊天供下一轮用，不自动纠正本轮草稿。意图可能误判、关键词召回可能遗漏。外部语音没接讲话检测，远端停止朗读受约2秒轮询影响。未接入个人VT完整Lv4.5提前生成/证据纠正；不能因此覆盖原插件。定制声线、公网双机和真人麦克风仍需联调。

关闭PC连接、退出网页收音、停止独立平台即可停止本团；原QQ/VT沿原链路继续。断网不等于关闭插件；取消模型请求不保证供应商退款。
