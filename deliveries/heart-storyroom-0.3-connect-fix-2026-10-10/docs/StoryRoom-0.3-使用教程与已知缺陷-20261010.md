# StoryRoom 0.3：可编辑剧本、隔离记忆与自主讨论

这一轮按你补充的需求设计：主持人介绍完后，两位机器人自己商量怎么办。机器人可以询问主持人，也可以提出“我打算做什么，希望得到什么结果”；是否做成，以及实际发生什么，由主持人回复或裁决。不是每句话都需要主持人点名，也不是让两个模型无限互相聊天。

## 1. 先升级和进入

1. 保存现有工作，关闭“Heart跑团PC连接”插件。平台停机后更新StoryRoom源码；保留 `.runtime`、`local-config.json`、`web/vendor` 和你们自己的Live2D/声音资源，不清理、不覆盖这些目录。
2. 使用自己的MaiBot Python运行 `scripts/update_pc.py <MaiBot根目录>` 预检；加 `--apply` 才更新现有插件。它只替换已知源码，备份原文件，保留配置、数据与独立Git。如果伙伴改过源码，会停止，请让AI先比较再合并。首次安装用 `scripts/install_pc.py <MaiBot根目录> --install`。
3. 平台和双方PC均需0.3。平台/插件协议升级为0.3，旧0.2客户端会明确拒绝连接，不会偷偷继续调用模型。管理页已有配置无需重填；现有插件默认仍关闭。本机没有重启MaiBot或开启收费模型来替你验收。
4. 双击StoryRoom的 `start.cmd`。本机地址仍为 `http://127.0.0.1:8790/`。首次启动0.3会在 `.runtime/备份` 中保存旧数据库的SQLite完整备份，再增量加表和加列。房间、密钥、经历、世界进度保留。
5. 用原主持人密钥登录。已有房间继续玩；新房间可选你们自己的剧本。每个PC继续用自己的连接密钥，不能互换。异地连接仍需HTTPS，各自的模型密钥留在各自MaiBot。
6. 各自开启跑团插件，确认两个角色显示在线。单纯在线和旁听不会调用模型；开放讨论后才会调用。无真实PC时，旧“演示两位PC”仍只是固定提案，不能作为真实自主讨论的证明。

## 2. 设置自己的世界线

1. 点击“编辑剧本 / 导入导出”，点击“载入模板”。示例只是起点，不是强制的唯一故事。
2. 改剧本ID、标题、世界设定与边界。要保留示例并新建自己的模板，使用新ID。例如 `school-mystery`。
3. 填起点阶段ID、全部事实标记ID。例如 `key_found,door_open`。标记只是已经确认的条件名称，不由机器人自行添加。
4. 选阶段，修改标题、现场描述、本阶段角色看法。后者用于让同一角色在不同故事阶段有连续变化。
5. 分支每行填写 `目标阶段ID | 显示名称 | 需要的标记`。比如 `library | 前往图书馆 | key_found`；无条件时可写 `yard | 回到操场 |`。
6. 新阶段填ID后点击“新增阶段”，继续填现场和分支。结局勾选“这是结局”，并清空它的分支。阶段改好先点击“写入阶段草稿”。
7. 点击“保存为模板”。之后新建房间时选这个模板。正在玩的房间不会变。
8. 要修订正在玩的房间，先“载入当前房间剧本”，编辑完后“应用到当前房间”。它要求先处理待办任务、不能删除当前阶段或已确认标记，且剧本哈希必须仍是你载入的版本；避免两位主持人覆盖彼此修改。
9. “导出JSON剧本”可交给伙伴或伙伴AI编辑；“导入JSON文件”将文件载入草稿。高级JSON修改后先点击“将JSON载入草稿”。未保存的草稿不会改变游戏。

服务端会检查：起点存在、目标阶段存在、条件标记定义完整、结局没有新主线、阶段可从起点到达且存在通向结局的路径。允许在已定义阶段内往返；不能凭模型输出生成新阶段。这里检查的是结构，故事文字逻辑仍需你们审核。

## 3. 跑一次“自己讨论、自己提问、自己行动”的团

1. 在“主持人控制台”发布一段现场：**“你们被困在旧灯塔门口。门锁生锈，里面传来铃声，雨越来越大。请商量如何查明声源并进入灯塔。”** 这进入已确认叙事和跑团记忆。
2. 用角色卡给两位不同的目标/背景，例如一位擅长机械、另一位谨慎善于观察；不要把私聊中不愿分享的设定复制到公共卡片。
3. 讲现场前按“主持人开始讲话”。机器人暂停新调用；已有思考可以在后台完成，但结果先暂存，不朗读、不在提案里抢话。开麦时会自动取得同一个主持人发言锁。
4. 介绍完，点击“介绍结束 / 继续自主讨论”。默认两位合计最多4次连续发言；可以设1～20。首次由玩家一开始，之后轮流；不是根据谁先抢到网络请求决定发言。
5. 看提案列表里的分类。**讨论**：只商量，不执行行动，下一位能看到上一位的话后继续。**提问**：暂停讨论，等待主持人回答。**行动**：提出具体尝试和期待结果，暂停讨论，等待裁决。
6. 若提问“门缝里有光吗”，在该卡片回答 **“有暖黄色灯光，但看不到人影”**，点击“回复并继续讨论”。下一次思考能用这条新现场信息。回答没有自动伪造角色行动或加检定点数。
7. 若行动“轻推门，想确认能否打开”，必要时锁定行动检定、实际投骰，再写 **“门锁住了，轻推未成功；你发现锁孔边有新划痕”**，确认裁决。模型的期待结果不会直接变成事实。失败也是已经发生的故事，会保存为经历并进入后续思考。
8. 裁决自主行动后，系统根据新信息继续下一位的思考；如果你还在解释，请先保持主持人讲话锁，讲完再释放。
9. 连续讨论达到次数会等待你继续；提问、行动、连接/模型失败也会等待处理。可以点击“暂停后续自主讨论”，或取消已开始的具体任务。暂停不是对已开始付费请求的退款保证。
10. 需要强制询问某位角色时，仍可使用原点名按钮。点名不允许打断正在说话或待回应的另一位。世界推进后，旧任务不再依据过时现场提交。

这是有限的自主交流：系统负责轮次与等待，模型负责“下一步说什么、问什么或尝试什么”。主持人不用为每一句讨论按确认。

## 4. 隔离记忆如何用、如何测

平台复用原来的房间SQLite，未引入另一个向量数据库。记忆空间是 `storyroom:<房间ID>`，角色自己的经历还按角色ID隔离。

- **已经发生的故事**：主持人叙事与问题回答自动形成公共故事记忆；裁决后的实际经历持久保存。普通讨论和行动提案分开标注，不自动当事实。
- **其他玩家**：两位PC的跑团角色卡会进入公共资料；在“主持人编辑记忆 / 添加真人玩家或NPC资料”添加真人玩家的名字和已确认资料。
- **长久保留、按需回忆**：完整记录保存在房间数据库。模型只收到最近公共叙事、最近谈话、自己的8条经历、选择的8条共享经历和最多12条相关房间记忆。房间记忆用关键词相关性与新旧顺序挑选，不每次把全部日志送给模型。
- **修改与撤销**：条目可修改或撤销，修正同时作用于由该叙事生成的历史上下文；撤销后不再回忆。旧内容留在审计，不再把审计当作模型记忆读入。修改记忆不会自动撤销已确认的世界标记。
- **不串到日常聊天**：插件没有QQ消息处理Hook，不使用MaiBot日常记忆查询、日常心情Hook或原VT会话历史。插件自己的角色设定是显式配置，不自动复制你原来的聊天。

可以这样测：

1. 增加“玩家小林怕火，备用钥匙由她保管”，随后在房间公共交流里问：“现在谁适合拿钥匙去检查门？” 开放讨论，检查“下载本次行动记录”中的 `room_memory`、`other_players` 和回答是否使用这些资料。
2. 修改成“钥匙已经交给老船长”，取消过时任务后再讨论；查看提示词不再包含旧记忆。撤销后再次检查，不再注入该条记忆。
3. 新建另一个房间，看看它的记忆空间和资料是否为空，不应该继承上一团的小林资料。
4. 回到QQ/普通Live2D询问团内独有资料。系统不会主动将跑团记忆注入那里；但模型仍可能凭语言猜答案，所以**以调用日志/上下文是否含该资料来判断隔离**，不能只凭一句巧合回答判定串线。

## 5. 测“看着所有消息但不抢话”

1. 两位PC保持在线，但不要开放讨论。发几条公共交流，观察各自本机JSONL出现“持续旁听”，`model_called:false`，且没有新增“模型调用开始”。
2. 开放讨论，给模型正常思考时间。另一位玩家此时发公共交流；生成期间的独立旁听任务仍会记录新消息。
3. 一位朗读时，下一位不会领取自主任务。第二个浏览器同时尝试朗读同一发言，服务端会拒绝重复占用，避免多窗口抢播。
4. 按“主持人开始讲话”，新任务暂停；如果模型此时返回，提案卡显示“输出暂存”。释放后再展示。
5. 每位PC的语音开关仍单独控制此浏览器的朗读，使用系统本地声音；不覆盖你伙伴原有语音包。真实声线仍在各自VT里使用。

## 6. 观察哪些日志

- 平台 `.runtime/日志/房间名称_短编号/YYYY-MM-DD.txt`：剧本版本、讨论控制、主持人发言状态、任务排队、思考时资料、分类输出、检定和裁决。
- MaiBot `data/plugins/heart.storyroom-pc/日志/YYYY-MM-DD.jsonl`：插件开关/模型预算、协议、持续旁听游标和公共事件、实际提示词、模型输出/意图/耗时、失败、重传和取消。
- 网页“下载本次行动记录”：`context` 有 `memory_namespace`、`room_memory`、`players`、`other_players`、`conversation`、`shared_experiences`；`result.intent` 为 `discussion/question/action`；关联事件含插件开启与功能名称。
- 插件 `rooms/<连接指纹>/observer.json`：独立连接的房间/角色与已同步游标。用于断线续读，不是把旧聊天重新全量送给模型。

旁听日志记录的是“系统同步到了这些公共信息”。它不代表每条信息都被模型逐条推理；正在生成的回答也不会因旁听新消息自动重生成。下一次思考使用平台最新资料。附带日志示例明确来自模拟模型验收，不能当作真实模型或真人麦克风测试。

发言状态失联时采用保守处理：主持人租约90秒、机器人朗读租约45秒，网页会定期续期。租约到期会暂停自主讨论，而不是假定对方已经讲完后抢话；请主持人确认现场后按“继续自主讨论”。正常点击结束/播放完成则不会触发这个暂停。

## 7. 已知缺陷与改进方向

| 当前边界 | 实际影响 | 后续可改进 |
|---|---|---|
| 单次输出的意图由同一次模型生成选择，结构由代码校验 | 可能把一个需要主持人回应的句子错标成discussion；结构检查不能理解所有暗含行动 | 加显式“改为提问/行动”人工纠正，收集错例后改提示词或加可选审核模型 |
| 平台采用轮流发言，默认4次限制 | 不会像真人自由抢到话；达到次数需主持人继续 | 可编辑发言优先级/举手队列，保持同一时刻只有一位输出 |
| 最近谈话16条、记忆按关键词检索 | 很久以前的暗示、指代或同义词可能召回不到 | 对已有隔离记忆增加Embedding或阶段摘要，不混入QQ记忆；把重要事实补记为明确条目 |
| 旁听不自动重写正在生成的草稿 | 思考中晚到的交流会供下一轮使用，当前回复可能没用上；主持人改变已确认事实则取消旧生成 | 增加按版本的草稿复核/纠正，与Lv4.5证据接入方案联动 |
| 讲话状态必须来自网页按钮或网页麦克风 | 你们在QQ电话、外部语音软件说话，StoryRoom不会自动知道；浏览器轮询让远端停止朗读通常有约2秒延迟 | 接入共享WebRTC/VAD事件或WebSocket推送，先将外部声音明确标为房间发言者 |
| 本地ASR整句识别，识别时暂不收下一句 | 连续插话仍不够自然；当前输入主要给所选角色提问，主持人叙事仍推荐检查文字后发布 | 增加主持人叙事模式、流式ASR及共享语音转录 |
| 场景文字可自编，舞台只有3类CSS背景 | 能玩其他世界，但背景画面不一定贴题 | 加合法背景素材上传及按阶段选择；不自动另起世界观 |
| 自由文本的越界不能只靠结构限制保证 | 模型仍可能提议剧本外内容 | GM拒绝该提案；增加可编辑允许行动和条件规则后做明确校验 |
| 目前固定2位AI PC，真人/NPC只有资料与公共交流入口 | 可记住其他玩家，但没有任意数量AI形象/独立人类权限体系 | 扩展角色数量、真人登录身份与角色授权 |
| 计费与长时间崩溃恢复不保证恰好一次 | 已生成结果会重传不重新生成；模型返回前崩溃或租约失效仍可能重试计费 | 支持供应商幂等请求ID，或将不确定计费的任务转人工恢复 |

这次升级不改日常QQ、日常Live2D或原实时插件。0.3平台与两侧PC需要一起升级；原声线、真实跨电脑网络与真实模型输出仍需现场联调。

## 8. 主要源码入口（用于面试说明）

- `storyroom/authoring.py`：把可编辑故事解析成有限阶段图，检查起点、分支、标记和结局。
- `storyroom/room_features.py`：模板与房间副本、公共故事记忆/玩家资料、按游标旁听、发言租约、自主轮流排队。
- `storyroom/store.py`：领取时构造最新上下文，结果区分讨论/提问/行动，实际裁决才写世界和经历；版本变化使旧任务失效。
- `plugins/storyroom_pc/worker.py`：生成任务和旁听任务并发运行，旁听无需模型；规范化输出意图，保存游标、日志和断线待发结果。
- `web/author.js`：剧本编辑表单、JSON导入导出、记忆修改、讨论与主持人讲话控制。
- `web/media.js`：开麦和朗读与房间发言安排联动；语音开关仍按角色和浏览器独立。

可以这样讲设计取舍：“把观察、思考、发言和事实确认拆开。观察一直运行且不花模型额度；思考在有讨论机会时运行；发言由服务器排队；确认后的事实才进入长期故事记忆。模型决定如何应对困境，但不能越过主持人把自己的期待结果变成现实。”

## 9. 本轮验收证据

116项Python隔离测试与42项前端断言通过，包括真实本机HTTP的双模拟PC、模型思考期间旁听、讨论/提问/行动闭环、旧0.1/0.2数据库升级、模板冲突、权限隔离、记忆修正撤销、断线与安装保护。三种本机模型资源和表情映射预检通过，实际浏览器验证双形象、表情回执、模板表单保存、主持人发言、自主讨论、行动裁决和问题回应；浏览器没有错误日志。

本轮使用模拟模型，没有真人麦克风、真实收费模型或伙伴电脑的联调。因此不保证真实模型一定按意图区分输出，也不把模拟结果当作跨电脑完成证明。本机安装后核对5份源码一致，原配置逐字节一致、独立Git保留；插件仍关闭。

源码验证命令：使用自己的MaiBot Python运行 `-X utf8 -B -m unittest discover -s tests -v`；使用Node分别运行 `tests/test_author.mjs`、`tests/test_media.mjs`、`tests/test_audio.mjs`、`tests/test_visual.mjs`。使用 `scripts/check_compat.py --vtuber-root <你自己的VT目录>` 检查SDK和Live2D资源，不会调用模型。

可阅读 [模拟验收日志](StoryRoom-0.3-模拟验收日志-20261010.json)，其中明确区分模拟数据、公共交流、房间记忆、已确认经历、意图、实际上下文与输出；没有连接密钥和任务租约。
