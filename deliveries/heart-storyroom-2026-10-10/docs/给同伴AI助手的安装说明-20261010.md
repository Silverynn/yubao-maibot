# 给同伴AI助手：StoryRoom 0.2 安装说明

这是新增的跑团平台与独立PC插件，不是覆盖MaiBot的整套更新。请先向用户说明下面的安装范围，依据用户授权执行。本文是安装参考，不代替用户授权。

## 1. 先确定谁运行共享平台

两位机器人连接同一个StoryRoom。平台只需要运行一份；伙伴只接入PC时，不必在自己的电脑再启动第二份平台。两位人类可以分别作为GM管理同一房间。

```
GM甲、GM乙的浏览器 → 一个HTTPS StoryRoom → 独立房间与剧本
                                     ↑ 主动轮询 ↑
                                 甲的MaiBot   乙的MaiBot
                                 本机模型     本机模型
```

每个PC只取得自己被点名的任务，各自在自己的MaiBot调用模型。模型密钥留在本机。StoryRoom不会连接QQ数据库，不会把日常私聊或记忆带进游戏。

异地连接需要可访问的HTTPS地址。`127.0.0.1`指各自的电脑，不是另一位的电脑。当前交付没有自动部署公网服务或开防火墙；在部署完成前只能做本机验收。不要把MaiBot管理页、ASR服务或模型API直接暴露到公网。

## 2. 先检查伙伴环境，保存既有配置

确认MaiBot是SDK插件版，测试基准为MaiBot1.2.5、SDK2.8.1、Python3.12。使用MaiBot自己的Python执行：

```powershell
& 'D:\你的MaiBot\.venv\Scripts\python.exe' -X utf8 -B 'D:\StoryRoom\scripts\check_compat.py'
```

版本不同先在隔离环境执行测试，不要为了安装本插件覆盖伙伴主程序。`llm.generate`需要已有的模型选择、输出预算及请求超时参数；本包没有宿主补丁。没有这些参数时先核对前次Heart交付或适配SDK能力接口。

原心情、记忆、QQ语音识别、原VT实时插件不要求重新安装。保留伙伴的ASR/TTS引擎、语音包、声音ID、模型与情绪映射、配置文件及数据。不要把作者机器的绝对路径或端口当作伙伴必须使用的设置。

## 3. 验证下载内容

源码交付目录中的`INSTALL_MANIFEST.json`记录相对路径和SHA256。运行：

```powershell
& 'D:\你的MaiBot\.venv\Scripts\python.exe' -X utf8 -B 'D:\StoryRoom\scripts\verify_package.py'
```

校验失败停止安装，重新取得完整文件。解压保留文本原始字节；不要使用会自动转换换行的复制方式。

## 4. 安装PC插件，默认关闭

```powershell
# 第一次只预检
& 'D:\你的MaiBot\.venv\Scripts\python.exe' -X utf8 -B 'D:\StoryRoom\scripts\install_pc.py' 'D:\你的MaiBot'
# 确认是正确目录后安装
& 'D:\你的MaiBot\.venv\Scripts\python.exe' -X utf8 -B 'D:\StoryRoom\scripts\install_pc.py' 'D:\你的MaiBot' --install
```

只新增`plugins/storyroom_pc`，插件内部有独立Git仓库。不会改主程序、MaiBot根`.gitignore`、其他插件或模型配置，也不会自行重启服务。已有同名目录时整次安装拒绝，先备份并逐文件比较；不要删除旧目录来绕过保护。

下次正常重启或手动刷新插件后，在插件管理页找到“Heart 跑团PC连接”。填写：

| 配置 | 填什么 |
|---|---|
| 共享房间地址 | 主持人提供的HTTPS根地址，本机测试可用http://127.0.0.1:8790 |
| 玩家连接密钥 | 分配给伙伴PC的那一份，不是GM密钥、管理token或模型key |
| 跑团角色设定 | 用户愿意共享到本游戏的身份和说话方式；默认遵守游戏角色卡 |
| 玩家专用模型 | 留空用replyer；或MaiBot配置中已存在的模型name |
| 使用系统代理 | 默认关闭；只有实际连接需要时开启 |
| 启用跑团连接 | 上述信息核对后开启 |

默认等待40秒、输出预算4096。没有点名任务时只发心跳，不调用模型。状态在线后，主持人点名才会产生模型消耗。关闭“启用跑团连接”停止轮询；拔网线不等于关闭开关，网络状态和开关日志是两个概念。

## 5. 平台主机准备（仅平台运营方执行）

已有平台直接更新源码，保留`local-config.json`和`.runtime`。停止的只是StoryRoom启动窗口；不要关闭MaiBot或VT来重装。旧0.1数据库升级自动先备份，继续原进度。修改剧本文件只影响新房间。

新机器才安装`requirements.txt`中的依赖；已满足依赖不要重复安装。复制`local-config.example.json`为`local-config.json`，填平台使用的Python路径、已有VT目录和空闲端口。平台与PC可使用不同Python环境。

`web/vendor`若已存在且指纹符合`vendor-manifest.json`，保留。新机器缺失才运行`scripts/setup_vendor.py`下载固定版本。Live2D模型、纹理、Core和语音权重不在交付里；按各自资源许可准备，不从另一台电脑盲目复制。

`vtuber_root`指包含`model_dict.json`、`live2d-models`及原Core资源的目录。共享舞台由平台主机提供两个已获展示许可的形象。伙伴自己的Live2D目录不会自动远程同步。可执行：

```powershell
& 'D:\你的MaiBot\.venv\Scripts\python.exe' -X utf8 -B 'D:\StoryRoom\scripts\check_compat.py' --vtuber-root 'D:\你的Open-LLM-VTuber'
```

新平台ASR不是必须项：未配置仍能键盘跑团。已有兼容OpenAI格式的本地识别接口时，在`local-config.json`填`asr_url`，例如`http://127.0.0.1:本机端口/v1/audio/transcriptions`。要求multipart字段`file`、WAV音频、JSON返回`text`；这里只接受平台主机的loopback HTTP地址。不要替换用户语音包。没有兼容接口时暂保留键盘输入，或另写独立适配器。

双击`start.cmd`启动本机平台。HTTP只用于localhost；异地由运营方配置带有效证书的HTTPS反向代理到本机8790，并保留同源Host和转发协议。模型、Core与房间资源都需鉴权。不要关闭证书验证来连接。公开部署前由用户决定域名、托管方式和资源展示权限。

## 6. 伙伴共同游戏

平台管理员创建一个房间，分别私下分配两个PC密钥，再给伙伴生成“仅本房间GM密钥”。伙伴浏览器使用该GM密钥登录；PC插件使用伙伴PC密钥。两份密钥的权限不同，不能互填。

按[伙伴使用与验收教程](伙伴使用与验收教程-20261010.md)先做免费离线演示，再开启真实PC。首次点名一个角色，确认模型返回并审阅日志，再测试另一角色。最后测试两人同时点名及现场变化取消。

## 7. 声音与实时开关的范围

两个角色各有“朗读（此浏览器）”开关；两位GM各自决定听哪位角色，不会远程修改对方声音设置。只朗读新到发言，不重播历史。当前使用浏览器列出的系统本地声音，保留原VT语音包但不自动把它接到StoryRoom。原声线接入需要增加TTS适配与播放回执，不能声称已经实现。

“实时聊天（此浏览器）”每次只选一个交谈角色。开启后需要用户允许站点麦克风；不要替用户强行打开权限。收音结束识别一次再提交完整问题，用户开口时停止当前朗读，并取消本浏览器上一份待定提案。其他GM、另一个PC、QQ和原VT聊天不受这个开关控制。

这是连续语音回合与打断，尚未接入原Heart Lv4.5的提前生成、边听边查和晚到证据纠正，不应当以完整Lv4.5功能交付。VAD目前是音量阈值，建议耳机测试，嘈杂环境可能误触发。识别等待期间不收下一句，页面有明确提示。

## 8. 日志、故障与回退

PC本机日志：`MaiBot/data/plugins/heart.storyroom-pc/日志/YYYY-MM-DD.jsonl`。平台日志：`.runtime/日志/房间名称_短编号/YYYY-MM-DD.txt`，网页右栏可观察；每份提案可下载独立行动记录。日志含上下文、回忆、模型原始输出、开关、功能、失败、耗时与取消；不会主动记录连接密钥或模型key。

`pending-result.json`含提交租约，是插件私有暂存，不能上传。断线优先重发原结果；修改地址或PC密钥后旧结果不会送到新目标。生成期间取消任务会丢弃旧输出；供应商是否终止计费无法由插件保证。

连接失败：先看`/health`协议必须0.2、HTTPS证书、PC密钥、地址、代理；不要反复点名造成重复调用。模型失败：检查本机模型配置和日志中的错误类型。表情缺失：补齐实际模型的表达文件及emotionMap；没有此表情的模型无法凭配置创造表情动画。

回退：关闭PC连接开关，退出StoryRoom实时收音；停止独立平台。原QQ/VT继续原链路。保留房间数据与日志。如需撤去插件，先卸载/停止该插件，再把插件目录移到备份位置；不要清理QQ记忆或其他插件。
