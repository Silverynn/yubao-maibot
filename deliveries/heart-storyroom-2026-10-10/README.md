# StoryRoom 0.2：双机器人跑团与有限世界线

人类当主持人，两位 MaiBot 当PC玩家，在同一个有限故事中提出行动，由主持人确认后果。平台使用 FastAPI + SQLite，PC通过独立SDK插件主动轮询。故事与日常QQ记忆分开保存。本轮不改MaiBot主程序、心情/记忆插件或原Live2D语音包。

在0.1原型上新增剧本版本锁定、跑团角色卡、行动绑定检定、已确认经历及修正/撤销、持续心情、同伴GM权限、断线结果重传、插件开关和实际输入输出日志。完整设计、测试与边界见 [实现与验收说明](docs/Lv2.5-实现与验收说明-20261010.md)。

## 本机先体验，不消耗模型额度

1. 双击 start.cmd，打开 http://127.0.0.1:8790/。这只启动StoryRoom；不会启动MaiBot、NapCat或原VTuber服务。
2. 从 .runtime/主持人登录密钥.txt 复制登录密钥到网页。不要公开密钥或提交 .runtime。
3. 使用旧房间继续，或新建世界线。内置剧本是《雾港最后一盏灯》，包含码头、小屋、灯塔和3个结局。第二个形象暂用旧角色占位，不代表已接入同伴的新模型。
4. 保存两个PC连接密钥，它们只显示一次；每台MaiBot只使用自己的密钥。
5. 没有真实PC在线时，点击“演示两位PC（不调用模型）”。固定发言明确标注离线演示，日志标注插件未开启。
6. 在提案中指定调查/动手/交涉及难度，点击“锁定检定”，再“为此行动实际投骰一次”。重复请求返回原点数，不重投。角色技能加值来自角色卡。
7. 填写裁决，选择已确认事实，设置心情/信任变化，点击“确认裁决与经历”。失败行动也可以确认失败的真实后果并形成经历。
8. 提案通过后，另一份基于旧现场的提案需要退回再点名；世界线只沿已定义分支推进，到结局后不能继续开启新主线。

初始心情50/100，信任0；主持人每次可调整心情−10～+10、信任−2～+2，最终限制为心情0～100、信任−5～+5。临时提案情绪不自动改变持久心情。角色卡里可填写过去/目标/三项技能0～3。卡片和已确认经历会实际进入下一次PC提示词。

## 接入自己的MaiBot

本轮PC插件默认关闭。安装不会重启正在使用的MaiBot，也不会修改其他插件或覆盖已有插件目录。用自己的MaiBot Python运行 scripts/install_pc.py，将MaiBot根目录作为参数，加 --install 才实际安装。

安装只新增 plugins/storyroom_pc，有独立Git仓库及插件自己的 .gitignore，不改MaiBot根目录的 .gitignore。下一次重启或手动刷新插件后，在管理页找到“Heart 跑团PC连接”，填写平台地址、此PC密钥和愿意带入跑团的角色设定，再开启“启用跑团连接”。

模型留空复用原 replyer 任务；也可以指定已有模型name。默认等待40秒、输出预算4096，未缩减日常模型预算。没有主持任务时只轮询，不调用模型。模型失败、超时、无效JSON均明确记录为失败。关闭插件停止轮询。

实测环境是MaiBot 1.2.5、SDK 2.8.1、Python 3.12；不支持旧式无SDK插件系统。伙伴安装见 [给同伴AI助手的安装说明](docs/给同伴AI助手的安装说明-20261010.md)。

## 两地共用一个房间

平台只在一台主机运行；两台MaiBot分别主动访问同一个HTTPS地址，各自调用本机模型。平台不接收模型API key、QQ数据库或私聊历史。127.0.0.1仅供本机，不能当异地地址。客户端禁止远程明文HTTP、禁止HTTP重定向，默认直连，确需系统代理可在插件配置中开启。

房间创建时锁定剧本副本和哈希，改剧本文件仅影响新房间。SQLite保存房间进度、角色状态和经历，重启继续旧故事。旧0.1数据库升级先通过SQLite backup API备份，再锁定当前剧本；无法恢复此前从未保存的剧本文件版本。

管理员可给同伴生成仅此房间的GM密钥；同伴可以点名、裁决和推进，不能创建别的房间、访问别的房间或继续转授GM权限。管理员可撤销密钥。不同GM同时操作仍遵守现场版本检查，日志记录操作者名字。

共享Live2D舞台读取平台主机的 model_dict.json 和授权模型目录。每位PC可使用自己的名字及模型映射，不修改个人VTuber配置。模型/Live2D Core不随交付包再分发；共享舞台提供分角色系统本地朗读、手动语音识别和单目标连续收音；没有接入原VT定制声线，场景为CSS。真实公网HTTPS部署和伙伴资源尚需两人联调。

## 日志与记忆

- 平台 .runtime/rooms.sqlite3：状态与审计事实来源，不自动删除跑团记录。
- 平台 .runtime/日志/房间名称_短编号/YYYY-MM-DD.txt：按房间/天导出的中文事件记录。
- MaiBot data/plugins/heart.storyroom-pc/日志/YYYY-MM-DD.jsonl：开关、协议状态、实际提示词、模型输出、耗时、失败与重传记录。
- 网页每个行动的“下载本次行动记录”：该任务的上下文、输出和关联事件，不含连接密钥或租约。
- 本机暂存的 pending-result.json 含提交租约，只在插件私有数据目录保存，不能公开或打包。断线后优先重发该结果，不立即再调用模型。

回忆只选择此角色已确认且有效的经历，最多8条，同阶段优先，再按时间。公共叙事先筛选再限量，不会被大量舞台回执挤掉。撤销/修正同时作用于回忆和进入提示词的历史，原始内容保留于审计；不会自动回滚已确认的事实标记。

## 验证和仍有的边界

使用MaiBot Python运行 -X utf8 -B -m unittest discover -s tests -v，使用Node运行 tests/test_visual.mjs、tests/test_audio.mjs、tests/test_media.mjs。

本轮85项Python离线测试、27项前端断言检查通过，并完成实际浏览器双模型舞台、提案、行动检定、心情和经历更新验收。包含真实本机HTTP＋两个独立模拟PC、实际SDK配置与生命周期。模型接口均模拟，没有运行真实付费模型或跨两台电脑。

主要不足：完整D&D/CoC规则、图形化剧本编辑、背景上传、情绪映射校正界面、原VT定制声线与嘴型、完整Lv4.5查询/提前生成/纠正、自动人格变化、分布式并发、真正的公网双机联调还未完成。自由文本是否越界仍需GM审阅，不能声称后台已自动理解所有剧情边界。检定只确认点数和条件，不自动裁决故事。进程在模型返回前崩溃或超过任务租约时，无法保证计费调用恰好一次。

换电脑只传源码/交付包；新环境才安装 requirements.txt，SDK测试使用自己的MaiBot环境。本机现有依赖和前端库不必重复安装。前端第三方库可用 scripts/setup_vendor.py 从固定版本下载并校验，许可见 THIRD_PARTY.md。主要代码入口：storyroom/store.py、storyroom/app.py、plugins/storyroom_pc/plugin.py、worker.py、web/app.js、web/stage.js、web/visual.js。

## 语音与实时交谈

两个角色各有朗读开关，只影响此浏览器；同一浏览器的实时收音每次只选一个角色。系统本地声音与原VT语音包独立，保留个人配置。识别复用平台现有本地ASR，完整输入才发给PC，所有提案仍需GM裁决。用户开口可停止朗读、取消自己待定的提案；生成期间现场检查会丢弃旧回答。当前不包含原Lv4.5的提前生成、边听边查和晚到证据纠正。
