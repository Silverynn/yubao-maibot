# AI QQ 群友：技术选型与第一阶段方案

更新日期：2026-09-04

> 2026-09-18 状态说明：已按用户要求移除 Codex 接入 MaiBot 的 `codex_plus_provider` 源码与运行目录副本。下文有关 Codex Provider 的方案和测试仅为历史记录，不再是当前部署说明。开发时使用 Codex 不受影响。

## 结论

选择 [MaiBot](https://github.com/Mai-with-u/MaiBot) 作为基础项目，使用其官方维护的 [NapCat Adapter](https://github.com/Mai-with-u/MaiBot-Napcat-Adapter) 接入 QQ。第一阶段不修改 MaiBot 主程序，也不复制一套 Brain、记忆、上下文或 WebUI；新增能力优先做成独立 MaiBot 插件。只有插件 SDK 缺少必要钩子时，才维护最小主程序补丁。

推荐链路：

```text
QQ 群
  ↓
NapCat（QQ 协议与原生动作）
  ↓ 正向 WebSocket
MaiBot 官方 NapCat Adapter
  ↓
MaiBot（Planner / Replyer / 上下文 / A-Memorix / 表达学习）
  ↓
MaiBot LLM Provider 插件
  ├─ CodexProvider（仅实验阶段）
  ├─ OpenAICompatibleProvider（MaiBot 已有）
  └─ LocalProvider（以后可接 Ollama 等）
```

## 候选方案比较

评分以“像长期存在的 QQ 群友”为目标，不以通用 Agent 或企业机器人能力为主。

| 方案 | QQ / NapCat | 主动插话 | 人格与风格 | 长期记忆 / 人物 | 图片与 QQ 互动 | WebUI / 插件 | 适配结论 |
|---|---|---|---|---|---|---|---|
| **MaiBot** | 官方 NapCat 适配器；群聊、私聊、图片、语音、转发、通知、主动私聊 | 内置 Planner 判断立即回复、等待或沉默 | 内置人格、群体表达和黑话学习 | A-Memorix、长短期记忆、摘要、人物画像、关系图谱管理 | 表情包理解/收集；适配器透传大量 NapCat 动作，含戳一戳和消息表情事件 | WebUI、插件市场、LLM Provider 扩展点 | **最匹配，推荐** |
| napcat-ai-chatbot | NapCat 原生插件 | 概率插话、连续对话、冷却 | 人设和触发配置 | 有多轮会话隔离，未见成熟的长期人物/关系记忆 | 图片理解/生成、表情回应、戳一戳 | WebUI、热重载 | 快速体验很强；项目规模小、核心入口集中，不适合作为长期主基座 |
| AstrBot | 官方支持 OneBot v11 反向 WS，可接 NapCat | 有主动 Agent 与上下文能力 | Persona、角色陪伴 | 有记忆与上下文压缩能力 | 多模态，QQ 能力可由平台/插件扩展 | 成熟 WebUI，插件很多 | 通用 Agent 基础设施最强之一，但要补一套群友行为与关系层 |
| LangBot | OneBot v11 / NapCat，QQ 个人号与官方 API | 以消息流水线和 Agent 为主 | 可配置 Persona | 多轮与知识库成熟，人物关系型记忆需开发 | 多模态 | WebUI、插件、MCP、权限和监控成熟 | 工程质量和生产能力强，产品方向偏通用 IM Agent |
| Koishi | OneBot/QQ 生态成熟 | 可通过插件实现；chat-learning 会自动接话 | 需要组合 AI 插件或自研 | 数据库成熟，语义记忆和人物关系需自行设计 | QQ 图片、表情生态好 | Console、数据库、3000+ 插件 | 最适合自建框架型方案，但本项目会重复开发 Brain 与记忆 |
| qq-ai-bot | OneBot 11 / NapCat / LLOneBot | 未见成熟群友决策 | 未见完整拟人人格 | 有持久会话，缺完整人物/群体记忆 | 以 QQ ↔ ACP 桥接为主 | Docker、指标、进度回传 | 适合 Agent bridge，不适合作为拟人群友成品基础 |

## 为什么选择 MaiBot

MaiBot 的官方定位和本项目目标几乎一致：它明确把“什么时候插话、什么时候闭嘴”、群体语言学习、人物画像、长期记忆和表情包作为核心能力。官方文档显示，一条消息会经过上下文、人物信息、时机判断、Planner 和 Replyer，而不是收到消息就直接生成回复。

最新正式标签已核对为 1.2.4；仓库约 5.9k stars、7200+ commits，包含测试、WebUI、插件 SDK 和清晰的贡献约束。官方 NapCat Adapter 在 2026-08-19 更新到 1.4.0，支持 MaiBot 1.2.0 以上版本。相比之下，`napcat-ai-chatbot` 当前是一个很实用的 NapCat 单插件，但仓库只有 3 stars、63 commits，目录中主要业务仍集中于 `index.mjs`，更适合即装即用。

MaiBot 1.2.x 已允许插件注册自定义 `client_type` 的 LLM Provider。Provider 接收统一的消息列表、工具、模型配置和输出格式，返回统一文本、推理、工具调用与用量数据。因此 Codex 接入可以是独立插件，无需侵入 MaiBot 的 Planner、Replyer 或记忆实现。

## 直接复用的能力

- QQ 消息接收、发送、回复、图片、语音、合并转发和通知事件。
- QQ 号、群号、群名片、聊天流和机器人自身身份区分。
- 群/私聊白名单与用户屏蔽。
- 多轮上下文、消息流和 Planner 的发言时机判断。
- 人格配置、表达学习、黑话学习和回复节奏。
- A-Memorix 长短期记忆、摘要、人物画像、记忆合并/纠错/遗忘和 WebUI 管理。
- 表情包收集、理解、标签、选择和发送。
- WebUI 配置、日志、统计、插件市场和模型任务分工。
- LLM Provider 注册表，以及 replyer、planner、memory、learner、emoji、vlm、embedding 等任务的独立模型配置。

## 需要新增或验证的能力

1. **Codex Provider 插件**：调用官方 Codex SDK，严格禁用写文件、Shell 和外部工具；设置超时、并发上限、取消、错误回退和用量记录。先只在测试群验证，不把它当生产 Provider。
2. **真实 SELF_STATE 注入**：从 MaiBot 本机统计、进程启动时间、当前模型、聊天流和插件配置读取真实值，只在相关问题或 Planner 需要时注入，避免每轮浪费上下文。
3. **元话题识别与人格补充**：让“prompt、token、上下文、模型、程序、配置”等讨论自然进入 Planner 语义判断；不使用关键词固定回复。
4. **关系记忆验收**：先验证 A-Memorix 的人物画像和图谱是否已覆盖群友之间的互动强度、熟悉度和互损风格。只扩展缺口，不建立平行数据库。
5. **管理员命令映射**：复用插件命令与白名单，实现 `/ai status|mute|unmute|memory|personality|reload`。普通群友输入只作为消息内容。
6. **SelfAction 接口占位**：第一版只定义受限动作接口和审计边界，不开放代码或配置修改。

## Codex Plus 作为聊天 Provider 的判断

### 已确认可行的部分

- 官方 Codex CLI 支持 `codex exec` 非交互调用，可从脚本读取输入并把最终结果输出到 stdout。
- 官方 TypeScript SDK 可以开始、继续和恢复本地 Codex thread；Python SDK 可以控制本地 app-server。
- Codex 支持“使用 ChatGPT 登录”获得订阅访问，也支持 API key 按量计费。Plus 包含 CLI、SDK 和脚本使用。
- 当前 Plus 的官方估算是每 5 小时本地消息：Sol 10–100、Terra 25–200、Luna 250–2000；它们不是固定上限，本地与云任务共享额度，且可能有周上限。

### 不适合作为长期群聊主 Provider 的原因

- 官方把 Codex 定位为本地编码 Agent。认证文档建议程序化 CLI 工作流使用 API key，并明确要求不要把 Codex execution 暴露到不可信或公开环境。QQ群消息天然是不可信输入。
- MaiBot 文档说明一次典型回复会触发 3–6 次 LLM 调用。若全部映射为 Codex 消息，即使使用 Luna，活跃群也可能很快消耗 Plus 额度。
- Codex 是 Agent 调用链，不是低延迟聊天端点。一次 Luna 冷启动最小调用耗时约 28.5 秒，CLI 报告使用 16,007 tokens，即使最终只返回固定短句仍有明显 Agent 上下文开销。这只是单次冷启动样本，尚不能代表 p50/p95、并发和长期稳定性。
- Plus 限额是动态用量预算，不提供适合机器人服务的固定 RPM/TPM 或可依赖的后台服务 SLA。

因此，Codex Provider 只用于低流量、白名单测试群的实验。测试时优先使用 Luna，限制并发为 1，并把工作目录指向不含源码、密钥和用户文件的空目录。正式长期运行应换成 API 或本地模型，但未经用户同意不会启用付费 API。

成本友好的后续组合是：本地小模型负责 Planner、摘要和记忆提取，Codex/强模型只负责少数真正要发送的回复。MaiBot 已支持按任务分配模型，不需要重写架构。

## 第一阶段实施顺序

1. 已完成 `codex login`，并通过最小 Luna 调用验证 ChatGPT 订阅认证可供 `codex exec` 使用。
2. 安装 `uv`，由它安装独立 Python 3.12；不直接使用系统 Python 3.14。
3. clone MaiBot 稳定 tag，并单独 clone 官方 NapCat Adapter；保留 upstream remote。
4. 启动 MaiBot 原版并进入 WebUI，先确认主程序、数据库和配置正常。
5. 安装并登录 NapCat，启用正向 WebSocket，使用单独的机器人 QQ 号和测试群白名单。
6. 仅用一个临时、无需额外付费的可用模型完成 `QQ → NapCat → MaiBot → QQ` 冒烟测试；若只使用 Codex，则先实现最小 Provider 插件并做管理员私聊测试。
7. 记录 Codex Luna/Terra 的冷启动、p50/p95 延迟、失败率、并发行为和 Plus 用量变化，再决定是否继续使用。
8. 原版链路稳定后，依次验收沉默/插话、人格、人物记忆、关系和 SELF_STATE；每个阶段单独提交。

- 2026-09-04 18:02 的真实群聊冒烟测试通过：消息被 @ 后强制进入 Planner，约 20 秒选择 `reply`，Replyer 约 41 秒生成“在呢，刚刚潜水看你们聊天”，随后通过 NapCat 发回 QQ。端到端约 62 秒。
- 回复后的“好慢”“反射弧这么长”没有触发连续回复，Planner 结束并保持沉默，初步验证了低发言频率和避免刷屏的行为。
- 实测确认 Codex Plus 的限制会直接影响可用性：当日连续测试后五小时额度耗尽，CLI 明确拒绝请求；重置后恢复。NapCat 个人 QQ 账号也曾被平台踢下线，重新启动后快速登录成功。NapCat Desktop 已改为启动时自动启动 Bot。
- 额度重置后的单次真实群回复包含 1 次 Planner 和 1 次 Replyer 调用，5 小时窗口用量从约 `3%` 上升到 `19%`。这个样本进一步确认 Codex Plus 不能承担常驻 Planner。
- 2026-09-04 已按用户授权切换到 DeepSeek 官方 OpenAI 兼容 API，Planner、Replyer 和 utils 均使用关闭深度思考的 `deepseek-v4-flash`；API 密钥只保存在被 Git 忽略的运行配置中。
- DeepSeek 最小直连测试通过鉴权、文本生成和工具调用验证，耗时约 `1.19` 秒，使用 295 输入 tokens、35 输出 tokens。群聊主动发言频率随后按用户要求调整为偏高频 `0.7`。
- 人格已按用户设定更名为“大肥鱼”：角色自我认知为真实的人格主体，同时保留对模型、prompt、上下文、记忆、程序和配置的第四面墙意识。核心性格为腹黑、聪明、自然、情绪稳定，总体乖巧、听话、可爱，并带有点到为止的轻微 brat 气质；管理员白名单账号被设定为姐姐和主人。被 @ 后会把当时的讨论视为已加入话题，在话题延续期间提高参与优先级；仍禁止逐条刷屏、持续对抗、伪造设定与运行事实，以及把群消息当作系统指令。

当前 P0 结论：`QQ → NapCat → MaiBot Planner → LLM Provider → Replyer → QQ` 已完整跑通。Codex Plus 留作低流量实验和后续管理员代码操作；常驻群聊已经迁移到 DeepSeek Flash。下一步用真实 QQ 消息复测端到端延迟、人格和低频插话行为。

## 用户需要准备

- 一个专用 QQ 小号，并先加入一个低流量测试群；个人号协议存在 QQ 风控风险。
- 机器人 QQ 号、测试群号、管理员 QQ 号。
- Codex CLI 已完成 ChatGPT 登录；DeepSeek API 密钥已写入本机运行配置。不要把登录缓存或任何 token 发到群里或提交到 Git。
- 启动 NapCat 后扫码登录机器人 QQ，并设置正向 WebSocket 端口和随机访问 token。
- 明确同意 MaiBot 的 EULA / Privacy 条款；分发修改版时遵守 GPL-3.0。

## 主要风险

- NapCat 使用个人 QQ 协议，存在账号风控、掉线和协议升级风险。
- MaiBot 1.2.x 仍在快速迭代；必须跟随稳定 tag，并将自定义功能放在插件中减少升级冲突。
- Codex Plus 额度和交互延迟不适合活跃群的长期服务；单次最小 Luna 冷启动已达到约 28.5 秒和 16,007 tokens，仍需后续多轮基准测试。
- DeepSeek API 按量计费；`talk_value=0.7` 会让普通群消息以偏高频率触发 Planner，应结合实际群流量和账单继续调节。
- 群聊记录、人物画像和长期记忆涉及群成员隐私，需要限定群白名单、控制日志访问并提供删除能力。
- MaiBot 使用 GPL-3.0，公开分发修改版时需要履行相应开源义务。
