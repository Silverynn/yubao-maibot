# Heart 同义去重修复与旧记忆整理

适用版本：Heart 记忆插件 1.3.1。此文不包含任何真实用户的记忆、日志或数据库。

## 为什么会有不同措辞的重复项

MaiBot 原生人物事实提取器可能在同一条用户发言后的多次回复中，再次提取相同事实。原生 A_Memorix 用写入正文构造幂等标识；完全相同的正文可跳过，但空格或改写后的句子会得到不同标识。旧版 Heart 写入前只检查“是否和旧事实矛盾”，把“不矛盾”直接当作“可新增”，没有单独判断“旧事实是否已经表达同一信息”。

## 新版如何处理

1. 先核实原发言者，且只取同一人物、同一会话中有效的旧事实；群聊不能因此读取私聊事实。
2. 去掉空白、忽略字母大小写后完全相同的事实直接跳过，不额外调用模型。
3. 其他相似措辞交给现有的冲突判断模型**同一次调用**区分 `duplicate`（旧事实已完整表达新事实，无新增信息）、`conflict`（同一属性互斥）、`clear`（不重复也不矛盾）和 `uncertain`（不确定）。`duplicate` 必须引用检索到的旧事实编号且达到 WebUI 中“同义重复最低把握程度”（默认 90%），否则暂缓写入，不能凭猜测自动删除旧事实。
4. 判为 `duplicate` 时，旧记忆保留、新内容不写入；日志新增独立的“长期记忆去重”记录，展示准备写入的内容、已有记忆、判断依据和跳过结果。真正冲突仍需本人私聊确认，确认前不替换。
5. 关闭“核实后自动写入长期记忆”而改用候选区时，同义旧事实也不再进入候选；同一证据的空格变体不会生成两个候选。

“有朋友”与“认为朋友很好”有不同的信息；“感谢有人陪聊”与“感谢某个具体的人陪聊”也可能涉及新增细节，不能仅凭字面相似就自动删除。LLM 判断并非完美，日志保留依据供人工检查。

## 已经存入的重复项怎么办

升级不会扫描、自动改写或批量删除历史库。数据清理前先关闭 MaiBot，备份完整 `data/a-memorix/` 和 `data/heart_observation/`，并核对目标人物、来源会话、原始证据和具体正文。只对明确同义、无新增信息的条目，通过 MaiBot 原生 `memory_delete_admin` 的预览与执行接口清理；不要直接运行 SQLite `DELETE`，因为向量、事实 claim、画像和图关系也需要一致处理。处理后重新读取本人有效事实核对，并在本地保留备份。不要把真实记忆或备份上传 GitHub。

如果暂时不进行人工核对，可让本人使用 `/我的记忆` 查看，发送 `/忘记 具体关键词`，在机器人展示精确目标后再私聊确认。关键词匹配到多项时，插件不会猜测要删哪项。

## 离线验收

- 同一事实只有空格差异：不调模型、不新增、产生易读去重日志。
- 同义改写：高把握且引用范围内旧事实时跳过；低把握或引用范围外编号时暂缓。
- 相关但不同事实：继续允许写入。
- 真正冲突：仍生成本人私聊确认；取消、超时或执行失败不把新事实冒充已存。
- 候选模式：已有同义旧事实不重复进入候选。

这些是离线模拟测试；伙伴首次接入真实 QQ/模型时，仍应使用虚构人物做小规模联机验收。
