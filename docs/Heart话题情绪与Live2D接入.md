# Heart 1.4：心情、话题情绪与 Live2D

普通聊天表情升级：新增“笑一个／装个生气表情”等自然语言表演判断，与真实情绪分开。原理、WebUI设置和真实模型测试结果见 [自然对话表情判断与测试](自然对话表情判断与测试.md)。

手动表情兼容修复：现已支持 `/表情 开心` 等命令临时展示约8秒，以及 `/表情 自动` 恢复自动；真实心情和话题情绪不变。详见 [手动表情冲突修复说明](Live2D手动表情冲突修复说明.md)。

## 这次完成了什么

可以把鱼宝理解成三个相连的部分：**MaiBot 负责聊天，Heart 管理角色状态，Live2D 把状态演出来。** Live2D 不另外找一个模型重新猜心情，避免两个地方各说各话。

| 部分 | 举例 | 什么时候变化 |
| --- | --- | --- |
| 长期心情 | 80/100，处于“开心”区间 | 沿用原来的对话刺激、限幅、冷却和时间恢复 |
| 话题临时情绪 | 对一道题感到疑惑，强度60% | AI判断产生、延续、改变或话题结束，由插件校验并保存 |
| Live2D表情 | 疑惑显示“问号”；结束后恢复“星星眼” | 展示插件已经确认的状态，不自行修改分数 |

因此，“心情80但正在疑惑”是正常状态。结束疑惑不等于把80重置成60；生气也不自动等于低落。临时情绪不按3秒或几分钟过期，沉默一天也不会仅因计时而清除；但重新进入 Live2D 网页会开始新会话，上一网页的临时情绪会结束并记日志，旧聊天不会暗中进入新网页的模型上下文。QQ 会话仍各自保持原规则。

## 一、现在怎么开始用

1. 像以前一样启动 MaiBot。需要QQ聊天时再启动 NapCat；只测网页不需要用QQ发消息。
2. 打开 MaiBot WebUI 的插件管理，找到 `heart_mood`，进入配置编辑。
3. 确认插件总开关开启。找到 **“话题临时情绪（独立于分数）”**，确认开启。本机已开启；仓库默认模板为了兼容旧用户仍为关闭。
4. 双击仓库 `.runtime/start_live2d_local.cmd`，打开 `http://127.0.0.1:12393/`。这是实际使用入口，不是本次离线测试脚本。
5. 浏览器已有旧页面时按 Ctrl+F5，避免继续使用旧表情代码。右上角会显示心情、临时情绪、话题和最近一次已确认状态的时间。
6. 如果显示“等待 MaiBot 处理首次 Live2D 对话”，先在这个网页发送一句普通文字，让 MaiBot 登记真实会话。不会拿某个QQ群的状态冒充网页状态。

仍是文字和表情模式：这次没有启用在线语音、麦克风或新的语音服务。

## 二、在界面里改什么

### 1. 原有长期心情

“自定义情绪状态”仍是原先按分数划分的区间，如低落0–35、平静35–65、开心65–85、兴奋85–100。区间必须连续覆盖0到100。这里改的是长期心情档位及说话风格，不是话题情绪。

已有的分数、基准值、恢复速度、AI加减分倍率、冷却和提示词均保留，没有恢复出厂设置。

### 2. 新增的“话题临时情绪（独立于分数）”

- `enabled`：开关。关闭后会结束已有临时情绪并记日志，不删除长期心情。
- `confidence_threshold`：默认0.7。模型自己报告的把握程度低于它，保留旧情绪；这不是经过统计校准的准确率保证。
- `guidance`：你可以修改的判断提示词。用于约定什么算话题延续/结束、怎样看待群聊插话等。
- `reply_wait_seconds`：默认4秒。生成回复前最多等这么久，让新情绪尽可能影响当轮回复；到时仍没评估完，则使用最近已确认状态，不无限卡住聊天。后台评估完成后更新面板和后续回复。
- `entries`：可新增、删除和修改分类，每一项有 `label`（分类名称）、`expression`（首选表情名）、`style`（该情绪下说话风格）。换形象后桥接层先检查当前模型是否有该表情；没有时按分类语义查当前模型的 `emotionMap`，仍没有则回退中性动作，文字情绪不丢失。

默认配置如下：

| 分类 | 表情名称 | 风格方向 |
| --- | --- | --- |
| 疑惑 | 问号 | 说明不确定之处、尝试澄清 |
| 开心 | 开心兴奋 | 自然分享喜悦 |
| 生气 | 生气 | 坚定表达不赞同，但不辱骂、不报复 |
| 难过 | 悲伤 | 温和安静、认真帮助 |
| 惊讶 | 感叹号 | 适度惊讶后继续讨论 |
| 害羞 | 脸红 | 略微腼腆，不强行制造亲密关系 |

例如想增加“撒娇”：可以新增分类并写好风格，但新分类若不是桥接层已认识的通用语义，应把 `expression` 配成当前模型已有的值。发送 `/表情列表` 可查看当前模型提供的名称/编号；换模型时可再调整插件配置。无法映射的分类仍能改变聊天风格和面板文字，但不会凭空生成模型没有的动画。

当前强度用于状态显示和回复提示，**并不意味着模型会把同一张脸精细混合成60%的表情**。当前是调用模型预制表情，也没有凭空新增“歪头”骨骼动画。

### 3. “Live2D常态表情”

当没有话题临时情绪时，按长期心情区间显示常态：低落→悲伤，平静→平静，开心→星星眼，兴奋→开心兴奋。修改分数档位的名称后，这里的 `state` 也要跟着改；找不到对应项时使用“平静”。

保存配置后后续处理会使用新配置。若 WebUI 的编辑页面仍没出现新栏目，重启 MaiBot 并刷新插件页面。删除一个正在使用的临时情绪分类，也会产生“情绪结束”的记录。

## 三、AI和插件分别干什么

AI像“观察员”：阅读当前原话、近期上下文和已有状态，给出建议，例如“继续疑惑”“问题解决，结束疑惑”。心情加减分与话题分类共用一次现有 `utils` 模型调用；Live2D不再加一次独立分类调用。关闭AI加减分、只开话题情绪时，分数仍可走关键词，分类仍需要这一次模型调用。

插件像“记账员和管理者”：检查返回格式、分类是否存在、变更证据是否真的在当前发言中、把握是否足够，然后保存状态、写日志、把风格要求交给MaiBot，并把展示状态提供给Live2D。

AI返回失败、超时或格式错误时，不凭空清除临时情绪。日志会写明保留原状态的原因。模型也可能误判话题边界，这时应根据日志调整 `guidance`，不能把程序校验当成语义判断绝对正确。

“话题结束”的默认规则：

- 明确“弄懂了，这个问题结束”，可以结束。
- 转入无关话题，可以结束旧情绪；若新话题触发另一个情绪，则记录旧的结束和新的产生。
- 同一话题换种说法、群里别人插一句话，不应轻易结束。
- “你现在什么情绪？”是查询状态，不应因此清空。
- 沉默、一次回复结束，不等于话题结束；重新进入 Live2D 网页会开启新会话，旧网页临时情绪结束并记日志。

## 四、QQ与Live2D之间的关系

心情和临时情绪都按 **MaiBot真实会话** 保存：群A、群B、与你的QQ私聊、Live2D网页会话互相独立。群聊是一个群共享一份“角色在这个群里的状态”，不是给每位群员打分。

QQ中没有形象，也会评估和保存小情绪，并通过临时提示词影响回复；询问“你现在是什么心情？为什么？”时，回复模型会收到实际状态及原因。模型是否准确遵循，仍应结合真实回复验收。

当前网页使用独立身份 `vtuber_local_user`；它不冒用QQ账号。网页左侧“新对话”不一定生成新的MaiBot身份，因此不能理解为点一次加号就自动重置一份心情。此版本不是让网页随意切换读取某个QQ群状态的控制台。

## 五、日志到哪里看

在**实际运行的MaiBot目录**打开 `data/heart_observation/logs/`：

```text
logs/
  QQ/       每个QQ群、私聊各自按天记录
  Live2D/   网页对话、状态与表情动作
  其他/     未识别平台或无法可靠关联的后台事件
```

文件名继续包含日期、群聊/私聊、会话名称和防重名短标识；内容之间空行分隔。系统不根据人名猜来源，不能确定的平台暂放“其他”。已有可核实会话的日志已重新分类。

你主要看这些记录：

- **临时情绪产生/变化**：谁说了什么、产生什么情绪、话题、强度、原因。
- **临时情绪结束**：之前是什么情绪、为什么结束、触发原话。
- **临时情绪判断**：本次延续旧状态，或判断失败所以保留。
- **心情影响回复风格**：本次提交了哪个心情/情绪风格；若评估尚未结束也会说明。
- **Live2D动作**：目标表情、关联心情/话题、发出状态和前端回执。
- 原先的记忆读取、新增、删除、冲突确认等记录继续保留，没有重新实现或替换原生记忆算法。

以下只是阅读格式示意，并非真实用户记录：

```text
时间：……｜临时情绪产生
人物：小明
心情：80 / 100
临时情绪：疑惑（强度60%）；话题：数学证明
原因：角色对当前解释仍有不确定之处
触发对话：你给出的两个结论似乎矛盾，我们再核对一下

时间：……｜Live2D动作
心情：80 / 100
临时情绪：疑惑（强度60%）；话题：数学证明
调用：Live2D表情接口 · 前端报告：已执行表情设置
目标表情：问号
```

“已发出展示状态”不等于前端已执行；“前端报告已执行”表示表情设置函数执行成功，也不是人眼验收的保证。尚未加载模型、表情名称错误、执行失败会分别记录。同一状态轮询不会每秒刷一条日志。

保留原来的清理策略：以本机日期为准，删除日期早于“今天减3天”的运行日志；也就是今天及此前3个日期可能同时存在。这只清理运行日志和对应审计事件，不删除原生长期记忆、当前心情和当前话题情绪。

升级前备份位于 `data/heart_observation/backups/before-topic-upgrade-20260928-104011.sqlite3`。这是用于回退的快照，不参加运行日志自动清理；如含不希望长期保留的旧聊天内容，需要由你决定何时移除备份。旧布局的导出文本已迁移，备份可供恢复。

## 六、建议这样验收

1. 开始网页对话，确认右上角不再是“--”。记录当前分数，不必为了测试强行改成80。
2. 讨论一件存在疑点的问题，观察AI是否判断为疑惑。不要把“用户不会做题”必然当成“角色疑惑”。看日志中的原话、判断原因和情绪分类。
3. 继续该话题，确认一次回答结束不会自动清空；等几秒不说话，也不会因为计时恢复。
4. 发“这个问题已经解决了，我们结束这个话题”，检查结束记录和恢复常态的表情回执。
5. 在QQ私聊中重复类似测试，问当前情绪；查看 `QQ` 文件夹。网页不应跟着QQ的状态变化。
6. 如果AI评估较慢，先看面板时间；它显示的是最近已确认状态，不是假装立即判断完毕。单次评估仍受原有AI超时设置约束。

本次自动检查：83项Python离线测试通过，前端控制器、旧版表情计时、真实编译包的纯文字表情处理检查通过。浏览器使用独立虚构数据库，实际加载鱼宝模型，验证80分+问号在回复结束后继续存在，再模拟话题结束验证分数不变且恢复常态，并核对动作回执。**没有调用真实模型，没有启动MaiBot或发送QQ消息**。真实聊天中的语义判断需要按上面步骤继续验收。

## 七、给同伴/AI助手的代码说明

这次没有新增修改 MaiBot 原生服务文件，沿用已有 Hook 和公共审计库。主要文件：

- `plugins/heart_mood/plugin.py`：配置界面、接收消息、回复前注入实际状态。
- `plugins/heart_mood/appraiser.py`：一次AI调用输出心情建议和话题情绪，校验结果。
- `plugins/heart_mood/emotions.py`：独立情绪生命周期与展示快照。
- `plugins/heart_mood/engine.py`：在原心情结算中调用新状态管理。
- `extensions/heart_shared/storage.py`、`readable.py`：新增状态表、按平台分类、易读日志。表结构是增量添加。
- `vtuber/heart_bridge.py`：同机状态接口和动作回执，只允许本机同源访问，不提供任意QQ会话读取。
- `vtuber/frontend/heart-controller.mjs`、`heart-avatar.mjs`：持久表情控制、面板和回执。
- `vtuber/frontend/yubao-expression-timing.mjs`：Heart接管期间不让旧3秒计时器抢回表情。
- `vtuber/src/open_llm_vtuber/agent/agents/maibot_agent.py`、`agent/agent_factory.py`：Heart启用时停止独立表情推测。旧手动表情命令不再越过Heart强改状态。
- `vtuber/maibot_client.py`：本地连接参数和独立网页身份。
- `vtuber/scripts/install_heart_bridge.py`：向固定版OLV `server.py` 注册路由、向前端 `index.html` 注册面板脚本。旧版编译前端补丁仍由 `apply_yubao_expression_timing.py` 安装。
- `scripts/upgrade_heart_channels.py`：先备份，再从原生会话登记表读取真实平台，迁移日志目录；不修改原生数据库。

迁移到其他电脑时：

1. 先备份并关闭两个程序；保留对方现有未提交修改、配置、数据库和模型许可文件，不能整目录覆盖。
2. 在仓库根目录用MaiBot虚拟环境执行 `scripts/install_heart_plugins.py --target <MaiBot目录>` 预检，成功后加 `--apply`。该安装器保留既有 `config.toml`，因此需手动在WebUI开启话题情绪。
3. 按 `vtuber/README.md` 的固定上游版本准备OLV，将上述定制源文件按相对路径合并；使用OLV虚拟环境运行两份安装脚本。版本锚点不匹配时停止，不强行替换。
4. 有旧Heart审计库时，用MaiBot虚拟环境执行 `scripts/upgrade_heart_channels.py --target <MaiBot目录>`，预检后再加 `--apply`。新安装且无审计库时不必迁移。
5. 启动OLV前设置 `HEART_MAIBOT_ROOT=<实际MaiBot根目录>`、`MAIBOT_WEBUI_JSON=<该目录>/data/webui.json`、`MAIBOT_WEBUI_WS=ws://127.0.0.1:8001/api/webui/ws`。不要复制这台电脑的密钥、QQ身份或审计库给别人。
6. 修改前端后强制刷新。接口目前用于同一台电脑；不把状态接口公开到公网或随意放宽跨域限制。

本机代码备份在仓库 `.runtime/backups/heart-emotion-topic-20260927/`；实际旧审计库备份在MaiBot自身的数据目录。回退时先停止两个程序，再有选择恢复插件和前端代码；除非确实要回到升级前数据，不要覆盖数据库，以免丢失升级后聊天。此轮没有替你提交或推送到GitHub。
