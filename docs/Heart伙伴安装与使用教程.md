# 给伙伴：从安装到测试

## 1. 先搞清楚你拿到了什么

这是MaiBot的增量扩展，不是一个包含QQ账号和全部运行环境的整合机器人。

- `heart.memory-audit` 1.2.2：观察原生记忆、按会话和日期导出中文日志、本人记住/查看/忘记、自动候选，以及人物事实冲突的本人确认流程。新指令见《Heart记忆升级1.2使用说明.md》。
- `heart.mood` 1.3.1：一个持久化心情值、关键词/可选AI评估、自定义分数区间与聊天风格，和记忆共用按会话分开的日志。

冲突保护是记忆扩展的一部分，不是第三个需要安装的插件。原生A_memorix仍负责实际存储、检索、人物画像和修改操作。

## 2. 准备环境

使用团队固定版本的MaiBot和已有依赖环境（团队README使用Python3.12、uv、Git；SDK测试版本2.8.0）。不要求额外安装SQLite软件，Python自带sqlite3库。

若完全没有MaiBot，先按团队仓库README准备基础实例：

```powershell
git clone https://github.com/Silverynn/yubao-maibot.git
cd yubao-maibot
python scripts/bootstrap.py
python scripts/bootstrap.py --apply
cd .runtime/MaiBot
uv sync
```

这些命令仅应在新的副本按README执行；bootstrap预检发现已有目录时不要直接删除重建。准备自己的配置、模型账号与NapCat连接后，再安装本包。README中管理员/QQ/群白名单占位值和本机启动路径必须自己核对；本包不代你改身份。

不要仅下载一个任意最新版然后强行打补丁。若接口不匹配，停下来比较代码。

## 3. 安装或更新

1. 关闭目标MaiBot，备份自己的代码、配置、数据。不要让机器人在半更新状态运行。
2. 把Heart包解压到独立目录，例如D:\Heart交接，不要直接覆盖整个机器人目录。
3. 在解压目录终端执行预检。D:\MaiBot替换成真正含bot.py和src的机器人根目录；如果来自团队bootstrap，通常是合作仓库中的.runtime\MaiBot。

```powershell
python scripts/install_heart_plugins.py --target "D:\MaiBot"
```

4. 第一行检查成功后才安装：

```powershell
python scripts/install_heart_plugins.py --target "D:\MaiBot" --apply
```

安装器检查补丁是否已应用、目标代码是否被你改过；已有config.toml一律保留。遇到冲突不强行覆盖，请比较文件。安装不是一个跨文件整体事务，应保留备份；安装器不会启动机器人、连接QQ或主动测试模型。

5. 正常启动你自己的MaiBot和NapCat。插件管理中确认两项Heart插件加载正常。记忆插件需要heart.memory.resolve、heart.memory.manual、heart.memory.candidates、heart.memory.manage和send.text能力；心情插件需要llm.generate能力。

## 4. 记忆插件怎么用

先保持原生A_memorix及自动人物事实写入开启，模型任务utils可用；使用冲突修正时原生fuzzy_modify_enabled也要开启。插件不会替你打开关闭了的原生系统。

| 配置 | 默认 | 含义 |
|---|---|---|
| plugin.enabled | true | 启用记录插件 |
| conflicts.enabled | true | 人物事实写入前检查冲突；额外模型调用 |
| conflicts.candidate_limit | 15 | 比较多少条检索候选；不是扫描全库 |
| conflicts.timeout_seconds | 20 | 冲突判断等待秒数 |
| conflicts.confirmation_minutes | 10 | 本人私聊确认有效分钟数 |
| auto_candidates.enabled | true | 原生自动提取先进入候选；关闭后直接走原生写入 |
| auto_candidates.max_pending_per_person | 20 | 每人候选上限 |
| auto_candidates.selection_guidance | 中文筛选规则 | 在WebUI修改AI判断哪些内容值得记住 |

如果旧配置没有conflicts节，代码使用默认值；界面保存后写入配置。默认日志和冲突保护会记录明文对话，开始多人测试前请告知参与者。

默认情况下，正常聊天由原生系统提取事实并放入候选，用户私聊 `/候选记忆` 查看并用 `/确认候选记忆 编号` 写入。也可直接 `/记住 内容`，私聊 `/我的记忆` 查看，`/忘记 关键词` 后 `/确认忘记 编号` 删除。详见独立的1.2使用说明。发现疑似冲突时，插件暂缓该条写入，私聊原用户展示新旧内容。例如机器人要求处理编号1：

```text
/确认记忆更新 1
/取消记忆更新 1
```

只选一个发送，编号以实际消息为准。只接受原用户在对应私聊的明确编号命令；普通“好的”不算确认。取消或到期不执行更新；确认执行前再核对计划和旧内容。QQ私聊必须可送达，必要时先加好友。

测试顺序：先明确说一条测试计划，确认候选后等日志确认原生写入；再明确改变决定，观察私聊询问。先测取消，再在有效期后用明确的新说法测试确认。不要以机器人嘴上说“记住了”作为存储证据。

范围限制：保护经过MemoryService的自动person_fact，不保证捕获直接调用原生内核的其他组件、管理员操作或所有摘要。检索可能漏掉旧信息，模型也会误判。原生更新并非整体事务；新内容存储后旧内容失效若部分失败，会记录并停止自动重试。原生计划回滚不保证清理保护流程预先写入的新事实，需人工核对。

## 5. 心情插件怎么设置

### 基础和关键词

只有一个0～100心情值，每个会话独立；群聊共享该会话的值，不是给每个用户做心理评分。初次创建默认50，重启保留。修改baseline不会立即重置现有心情；它是初始值和后续时间恢复目标。

时间恢复在收到下一条消息时一次结算：程序读取上次保存心情的时间，按`recovery_per_hour`向**当前**baseline靠近；长时间没有消息时，下一条日志可能出现大于`mood.max_delta`的总变化。`max_delta`只限制该条消息的情绪刺激，不限制时间恢复。重启本身不会把心情改成baseline。日志里的“数值变化原因”会写明间隔、速率、目标和恢复分数；如果新旧记录都保存了目标，改变baseline后还会明确提示目标变更。旧记录没有保存历史目标，不能事后确定旧配置。

`mood.max_delta`默认8，是所有模式单条刺激的总上限；`mood.cooldown_seconds`默认60，是同一用户重复刺激的冷却时间。`rules`可改感谢/贬低/共情关键词和对应分数。词组不是出现就必然加分，程序还会保守处理一些引用、否定和假设。

### 开启AI评估

在“AI心情判断（可选）”开启ai.enabled。默认关闭，不会一安装就增加AI评估费用。使用现有utils模型，不要再把密钥填进插件提示词。

| 配置 | 新安装默认 | 使用方法 |
|---|---|---|
| ai.max_output_tokens | 4096 | 输出预算，不是心情分；旧400已移除 |
| ai.timeout_seconds | 20 | 单次后台等待时间；已有6秒配置会保留，建议手动改20 |
| ai.delta_multiplier | 1 | 0.5温和，1原建议，2更敏感；允许0～3 |
| ai.positive_limit | 8 | AI每条最多加分 |
| ai.negative_limit | 8 | AI每条最多减分，填正数 |
| ai.confidence_threshold | 0.7 | 把握不足则不计刺激 |
| ai.fallback_keywords | false | 仅模型失败时是否改用关键词；低把握不是失败 |
| ai.guidance | 中文默认提示 | 怎样评价对话的补充要求 |

AI开启时不与关键词重复加分。计算顺序：AI原始分数→置信度检查→倍率→AI方向上限→总上限/冷却→0～100边界，时间恢复另计。AI建议+4、倍率2、AI加分上限6，在总上限8且未冷却时刺激是+6。

后台评估不阻塞聊天，结果可能赶不上当次回复，而影响后续回复。当前实现全插件单队列，最多排队8条，排队超过30秒跳过模型；评估结果不是无限保证即时。输入包含原话、同会话最近3条用户发言和心情快照，不读取整个长期记忆库。每条符合条件的消息可能增加一次模型调用，向测试参与者说明数据流向。

### 自定义情绪区间和回复风格

在“自定义情绪状态”保持states.enabled开启，编辑entries列表。每项包含name、minimum、maximum、style。

默认：低落[0,35)、平静[35,65)、开心[65,85)、兴奋[85,100]。名称不重复，区间连续覆盖0～100，不能重叠。想增加一档，要拆分原有区间。例如开心65～75、非常开心75～85。最高100包含在最后一档。

style决定“如何回复”，ai.guidance决定“如何判断情绪”，不要混淆。开启states后不用旧prompts.low/neutral/high选择风格，但prompts.safety仍然生效。关闭states回到旧三档。

## 6. 日志在哪里

目标MaiBot目录：

```text
data/heart_observation/
  logs/YYYY-MM-DD_群聊_群名称_短编号.txt    每个群每天一份
  logs/YYYY-MM-DD_私聊_对方名称_短编号.txt  每个私聊每天一份
  当前心情.txt             最近值、原因、触发原话
  events.sqlite3           事件/心情/确认流程数据库，不是原生长期记忆库
  install-manifest.json    安装器自己的文件校验收据
```

不用发指令，按日期和会话名称找对应txt；重新打开可看到更新。后台记忆可能晚于回复写入，不能只看紧跟消息的那一条。旧版同日混合文件会在升级重建成功后拆分；超过三天的旧日志和对应审计事件自动清理。细节见《Heart会话日志与三天清理说明.md》。

每条日志的“会话”行会注明群聊名称，或与某人的会话；心情值按会话独立保存。相邻日志可能来自不同会话，例如群聊55分、私人会话60分，并不表示中间加了5分。判断一次变化要看同一会话内的“心情变化”事件及其刺激、时间恢复明细。无法确认名称时显示“名称未记录”，不暴露内部会话编号。

- 检索候选：原生查询返回的内容，不代表模型采用。
- 模型记忆参考：识别到进入模型输入的参考，不代表最终采用。
- 存储结果：原生服务是否报告存储ID，不能只看口头承诺。
- 心情变化：触发原话、判断方式、原因、AI原始建议、倍率、冷却/限幅、恢复和最终变化。
- 如果AI建议0但总变化不为0，请看“数值变化原因”；这通常是先前未结算的时间恢复。本条对话的AI判断原因不能解释时间恢复。
- 冲突确认：发现、等待、取消/超时、执行、成功或部分失败。

日志不直接铺开散列、metadata和JSON；较长内容节选。需要深查时看数据库。没有记录模型隐藏推理。

原生忘记/删除不会自动清除日志里的历史副本；这不是彻底擦除隐私功能，不要宣称已经实现完全遗忘。不要把logs、events.sqlite3或实际配置公开发给同伴。

## 7. 验收和回退

离线测试：在解压包根目录，使用目标环境的Python：

```powershell
& "D:\MaiBot\.venv\Scripts\python.exe" -m unittest discover -s tests -p "test_heart*.py"
```

测试数据写到交付包的.runtime/test-data，不往运行实例塞测试记忆，也不调用模型。不要把测试数据提交仓库。`verify_heart_integration.py`应只在隔离测试实例使用：它加载目标plugins下的插件，不要在装有未知第三方插件的生产实例随便运行。

运行验收：同一私聊分别测试感谢、反讽、普通提问；相隔至少60秒，检查原因和实际变化，重启检查持久化。用另一用户/群检查隔离。对冲突测试取消、本人确认、他人确认拒绝、超时。AI每次分数不保证固定。

最小回退：关闭ai.enabled回到关键词；关闭conflicts.enabled停止写入前检查，保留记录；关闭states.enabled回到旧三档。先关闭功能比删数据更安全。

彻底回退请停机并参照底层改动清单，关闭两个插件后按反向顺序撤销属于Heart的五份补丁（先git apply --reverse --check再实际apply），或从自己的备份恢复对应文件。不能整个src覆盖回去破坏别人的修改。保留data，直到确认备份和需要的历史。

## 8. 如何继续团队协作

提交/共享plugins/heart_*、extensions/heart_*、五份patch、安装器、测试和新教程；不要提交.runtime、运行配置、密钥、真实日志和QQ登录态。仅提交外层仓库不会自动包含实际运行目录的临时改动。

此次包包含Heart扩展，不包含原使用者在maisaka_generator_base.py、src/chat/utils/utils.py等其他文件上的定制；若要整机一致，另做范围核对和脱敏，不能声称本包等于完整机器人克隆。
