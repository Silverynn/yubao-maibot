# 鱼宝 Live2D 表情修复与测试说明

更新日期：2026-09-27。针对本仓库固定的 Open-LLM-VTuber 后端和前端版本；不是任意版本通用的替换包。

## 先说结论

模型原本已经带有表情素材，不需要重新下载角色。实际检查到 45 个 Expression 定义（其中也有外观/道具控制，不等于 45 种情绪）；现在配置中的 17 项情绪映射全部能对应到模型内的名称。

本次修复了“表情指令存在，但纯文字模式不执行”“表情刚出现就被对话结束事件清除”，以及纯文字/表情任务可能提前结束、分段回复抢先恢复平静的问题。没有修改 MaiBot 的记忆、心情数值、QQ 接入和数据库。

## 一、小白测试步骤

1. 启动你本机的 Live2D 启动程序。此电脑使用仓库 `.runtime/start_live2d_local.cmd`，实际程序在 `.runtime/Open-LLM-VTuber-pinned/`。它和 MaiBot 是两个程序。
2. 打开 `http://127.0.0.1:12393/`，按 Ctrl+F5 强制刷新，等角色加载完成、左上角显示“已连接”。这里只表示网页连上 Live2D 服务，不代表 MaiBot 也已启动。
3. 在这个网页下方的消息框发送 `/表情 开心`。眼睛应变为开心形状，约 3 秒后回到平静（模型本身还有短暂渐变）。
4. 再试 `/表情 生气`、`/表情 疑惑`、`/表情 难过`。前两者会显示怒气符号和问号。每次间隔几秒。
5. `/表情 平静` 可以立即恢复；发送 `/表情` 或 `/表情 列表` 查看可选项。
6. 这些是 **Live2D 网页专用的本地测试指令**，不发 QQ、不调用大模型、不改真实心情值；MaiBot 关闭也能测试。不要在 QQ 中发送并期待同样效果。
7. 普通聊天仍需要另外启动 MaiBot。正常回复会按已配置的判断方式选择表情，不需要每次输入测试指令。

保持当前“文字 + 表情”模式即可，本次没有启用 Edge 在线语音、Fish Audio 或麦克风服务。

## 二、为什么以前没有表情

### 1. 原前端把换表情塞进了“有声音才执行”的分支

简化后的错误逻辑是：

```javascript
if (有音频) {
  换表情();
  播放声音();
}
```

你选择不使用语音，音频为空，于是连表情也被跳过了。现在变为：

```javascript
if (有表情指令) 换表情();
if (有音频) 播放声音();
else 完成本次播放任务();
```

声音和表情是同一个消息包里的不同字段，不该相互绑定。无声回复现在也会更新字幕，不再停在 Thinking。

前端修复由 `scripts/apply_yubao_expression_timing.py` 实施；它检查编译文件中的准确位置，先在内存完成全部校验，再写回。前端版本不匹配会报错停止，避免半份补丁。重复运行安全。

### 2. 表情刚出现，又被“本轮结束”立即抹掉

浏览器实际记录曾显示：设置“生气”后约 0.2 秒就执行了恢复平静。人眼还没看清，表情就消失了。

`frontend/yubao-expression-timing.mjs` 现在统一管理短暂表情：期间忽略自动结束重置，3 秒后自行恢复；手动选择平静仍然立即生效。换角色时，旧计时器不能影响新角色。

同一轮 MaiBot 如果分几条回复，后续段落也不再抢先发送“平静”覆盖已经出现的表情。

### 3. “放进发送队列”并不等于“已经送出去”

原来的空语音回复可能只入队，却没被记入需要等待的任务列表。本轮随后结束，清理队列时把还没发送的表情一起取消了。

`src/open_llm_vtuber/conversations/tts_manager.py` 现在会等待 WebSocket 的实际发送完成，再把任务算作完成；普通无声文字、纯表情、带语音任务保持发送顺序。断线会返回错误，中断会取消等待，不会一直卡着。这里的“发送完成”是服务端发送成功，不等于已经证明浏览器完成渲染，后者还通过实际页面测试验证。

### 4. 部分分类名称和模型配置对不上

表情判断文件里的 `heart_eyes/gloom/drool/blank_stare` 与模型配置里的 `love_eyes/gloomy/drooling/blank_eyes` 不一致，已统一；同时补充 `confusion → 问号`。

## 三、当前谁决定表情？是否等于心情插件？

**目前不是直接读取 Heart 心情插件的数值。** 本机没有启用额外的表情分类模型，所以普通回复先走 `maibot_agent.py` 的 `infer_reply_emotion`，按回复里的明显线索挑选开心、生气、难过、惊讶或疑惑，否则平静。例如“好耶”会选开心；普通说明通常保持平静。

因此“她脸上平静”不代表心情值没有变化，也不能保证每一句语义上的开心都被这个简易规则识别。本次解决的是表情执行链路，不是把关键词判断包装成 AI 情绪判断。

`maibot_expression.py` 保留了额外 LLM 分类路径；只有配置好并启用对应模型时才使用。更贴合题干的后续设计是让 Heart 输出统一的 `emotion_label / intensity / reason`，连接程序只把标签翻译成模型的表情名称。这样文字风格、数值日志、Live2D 才有同一个状态来源。

## 四、哪里看表情日志

当前 Live2D 运行目录的 `logs/debug_YYYY-MM-DD.log` 会记录：

```text
Live2D 表情 | 来源=手动测试 | 表情=问号
Live2D 表情 | 来源=回复线索 | 分类=joy | 指令=开心兴奋
Live2D 表情 | 来源=回复线索 | 分类=neutral | 指令=保持当前表情
```

`保持当前表情` 表示这一段没有再覆盖前面的表情，不是调用失败。这是 Live2D 自己的运行日志，**还没有合并进 Heart 的按会话记忆/情绪日志**。上游日志默认按日期写入、10 MB 轮换、保留 30 天，与 Heart 的三天清理规则是两套配置。

## 五、表情包和 Live2D 表情不是同一个功能

- Live2D 表情：改变同一个模型的眼睛、嘴巴、问号、怒气符号等。
- QQ 表情包：一张图片或 GIF，需要聊天界面绘制图片。

检查的是你当前安装的这版接入，不是在断言所有 Open-LLM-VTuber 版本都不能展示图片。

MaiBot 的 WebUI 序列化代码本身能输出 `text / image / emoji` 消息段；但本机连接文件 `maibot_client.py` 的 `extract_speech_text()` 只保留 `type == "text"`，`stream_maibot()` 也只把取出的文字交给 Live2D Agent。因此：

| MaiBot 实际返回 | 你当前 Live2D 界面的结果 |
| --- | --- |
| 普通文字 | 正常显示，按规则选择模型表情 |
| 文字 + 图片/表情包 | 只显示文字；图片段被跳过 |
| 只有图片/表情包 | 算作收到回复，但没有可显示的文字；通常再等最多约 5 秒收后续回复，然后结束，画面没有表情包 |

不会自动把 GIF 转成模型表情，也不会因为页面不能显示就自动补发到 QQ。原本 QQ 会话自己的表情包发送流程不受本次修改影响。

本次没有新增图片/GIF 渲染。若后续要接入，应保留结构化图片段，并给网页增加安全的图片显示组件（验证类型、限制体积和来源），而不是把图片描述交给 TTS 冒充已经展示图片。

## 六、同伴需要哪些改动

修改/新增的文件都在本仓库 `vtuber/` 下：

- `model_dict.json`：新增疑惑映射。
- `src/open_llm_vtuber/agent/agents/maibot_agent.py`：本地表情测试、分段保持、表情日志。
- `src/open_llm_vtuber/agent/agents/maibot_expression.py`：统一分类名。
- `src/open_llm_vtuber/conversations/tts_manager.py`：发送完成等待和中断处理；这是 Open-LLM-VTuber 后端原生文件的补全，**不是 MaiBot 原生文件**。
- `frontend/yubao-expression-timing.mjs`：计时恢复、推迟自动重置。
- `scripts/apply_yubao_expression_timing.py`：为固定版本的前端编译包应用补丁；编译包本身仍不作为本目录的分享内容。
- `scripts/test_agent_changes.py`、`test_expression_timing.mjs`、`test_silent_expression.mjs`、`test_silent_delivery.py`：离线回归测试。

在同伴已有的、版本一致的完整 Open-LLM-VTuber 目录中，先备份上述同名文件，再复制定制文件到相同相对路径；不要覆盖 `conf.yaml`、密钥、聊天记录或整套 MaiBot。运行：

```text
python scripts/apply_yubao_expression_timing.py
python scripts/test_agent_changes.py
python scripts/test_silent_delivery.py
node scripts/test_expression_timing.mjs
node scripts/test_silent_expression.mjs
```

Python 要使用该程序的虚拟环境。Node 只用于离线前端测试；程序日常运行不需要额外开一个 Node 服务。重启 Live2D 后强制刷新网页。
